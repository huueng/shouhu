## 一、网络：路由器重启后，DNS 已经好了

上一轮记录的「域名解析不了」**已经消失**。这次的实测结论：

| 检查 | 结果 |
|---|---|
| `ping6 2408:8220:7f1e:...`（中继 IPv6 字面量） | 通，43ms |
| 域名解析 | **成功**（报错信息里已经带出解析到的 IPv6 地址） |
| 上报到 `https://shouhu.example.com:812/api/report?k=...` | 连通，但返回 **HTTP 401 令牌不对** |

所以 DNS 这一环不用再管了。现在卡在令牌：手机里存的 `k=e7132df323c1984b`，
和 NAS 上中继当前配置里的设备令牌对不上（多半是重装 / 点过「重新生成令牌」）。

**要你做的**：打开中继网页 → 设备列表 → 复制那台老人的上报地址（或重新扫码），
用下面任一方式写进去，**不用手打**：

```
tools\provision.ps1 -SetUrl "https://你的域名:812/api/report?k=新令牌"
tools\provision.ps1 -Report            # 立刻上报一次并打印结果
```

顺带说明：**移动数据下也能上报**。这台机器的移动网有公网 IPv6
（`rmnet0: 2408:8422:...`），域名只有 AAAA 记录也能解析，所以不连 WIFI 同样能通。

## 二、内网 WIFI 模式：显示与上报都对了，但中继原来把名字丢了

真机现象全部符合预期：

- 顶部网络区显示 `FF`（WIFI 名 + 格数），不再是运营商
- 桌面只剩 飞牛播放器 / 守护同步端 / 抖音TV / 无线网络，电话、短信、联系人已撤掉
- 断开 WIFI：红条「无线网络被关掉了，家人看不到位置」，网络区变「WIFI 关」
- 设置页：「当前 WIFI：FF　只记录名字，不限制连哪个网。点一下刷新」

**但发现一个真 bug**：老人端确实把 `wifiName / intranet / netFlag / ipv6` 发出去了，
可**中继的报文结构里根本没有这几个字段**，解析时被静默丢掉，`/api/status` 也不输出。
结果就是家人端只能显示成「WiFi 」后面空着 —— 你要的「上报只写 WIFI 名字」等于没落地。

已修（中继 1.6.1）：

- `Report` 增加 `WifiName / Intranet / NetFlag / Ipv6` 四个字段
- 顶层与 `status` 里两种写法都解析
- `/api/status` 输出 `wifiName`，内网模式下额外输出 `intranet / netFlag / ipv6`
- 只报定位的包（不带名字）**沿用上一次的名字**，不会把家人端刷成空
- 单测 `TestWifiNameSurvivesMerge` 覆盖这两条

实测（本地中继）：

```json
{

 "wifi": true, "wifiName": "FF", "intranet": true,
 "netFlag": "ok", "ipv6": "2408:8220:7f1e:5821:c69f:4cff:fe83:e97f",
 "lat": 39.900586, "lon": 116.394435, "version": "2.8.3(17)", "online": true
}
```

⚠️ 注意：**中继必须升到 1.6.1** 家人才看得到 WIFI 名字。旧中继功能不受影响，只是没这几项。

## 三、远程命令：闭环打通了，中途揪出「命令被补发吞掉」

链路：家人端点按钮 → 中继入队 → 老人端下次**实时**上报时捎走 → 执行 → 再下次上报带结果回来。

实测结果：

| 步骤 | 结果 |
|---|---|
| `POST /api/cmd {"cmd":"health"}` | 入队成功，返回命令 id |
| `POST /api/cmd {"cmd":"rm -rf"}` | 拒绝：「不支持的命令」 |
| 实时上报一次 | 取走命令并执行 |
| 再上报一次 | `cmdResult = {"cmd":"health","ok":true,"msg":"10/10 正常"}` |
| `POST {"cmd":"restore"}` | 执行成功：上报地址回到基线 `shouhu.example.com`、内网模式回到关闭、桌面卡片回退到基线 |

**中途遇到的真 bug**：第一次发 `health`，队列一直 `pendingCmds=1`，命令永远不执行。
原因是中继把命令捎在**任意一个** `/api/report` 响应里，而老人端补发历史报文
（那次积压 90 条）也打同一个地址、但**没人看补发请求的响应** —— 命令就被补发吞了。

修法：补发请求带 `live=0`，中继只在 `live=1`（实时上报）时才捎命令。
顺带修了 `pendingCmds` 把「已下发未回结果」也计入的问题。

⚠️ 一个必须知道的行为：`restore` 会把**上报地址也恢复成基线**。
如果基线里的令牌是旧的，恢复完就和中继失联了。恢复前先确认基线地址可用。

## 九、补测：主动上报的「扫一扫」打不开相机（2.9.4 已修）

你说荣耀 Magic2 上扫不了，这台 COL-AL10 同样扫不了。查到**两个原因，缺一个都打不开**：

### 原因 1：FileProvider 没配 cache-path（直接抛异常）

扫码的实现是「调系统相机拍一张 → 回来用 ZXing 解」，照片写在
`cacheDir/qr/scan.jpg`，再 `FileProvider.getUriForFile(...)` 交 URI 给相机。
但 `res/xml/file_paths.xml` 里只配了 `external-files-path` / `external-path`，
**没有 `cache-path`** —— `getUriForFile` 立刻抛 `IllegalArgumentException:
Failed to find configured root`，被 catch 成一句 Toast「打不开相机：…」，
相机根本不会启动。这就是「点了没反应」的直接原因，跟机型无关。

### 原因 2：锁定任务模式下相机不在白名单

就算 URI 修好，本应用是锁定任务的唯一允许包，`startActivity` 去调
`com.huawei.camera` 会被系统拦掉（SecurityException）。
原来的代码完全没有处理这一点。

### 修法

1. `file_paths.xml` 加 `<cache-path name="qr" path="qr/" />`
2. 扫码前用 DPM 把**解析出来的相机包**临时加进 `setLockTaskPackages`，
   拍完（`onActivityResult`）立刻收回到「只有桌面卡片」的白名单；
   `onResume` 再兜一次，防止相机崩溃导致相机被长期留在白名单里
3. 没装相机 / 被拦 / 建不了目录，都改成明确提示，不再静默失败
4. 解码失败、「扫到的不是上报地址」从 Toast 改成对话框 ——
   Toast 3 秒就没了，家人在手机上根本看不清

### 实测（本机）

```
12:41:44 ElderSettings: 扫码：相机包 com.huawei.camera，锁定任务临时放行=true
         → 系统相机正常打开（com.huawei.camera/.ThirdCamera）
         → 按快门 → 预览页 → 点「确定」
12:43:09 ElderSettings: 扫码结束，锁定任务白名单已恢复
         → 回到设置页，锁任务白名单已回到「只有桌面卡片」
```

解码器单独验证（用中继同款二维码，`qrgen` 生成的 560px PNG）：

```
adb shell am broadcast -a com.elder.launcher.ADMIN --es cmd qrdecode \
  --es arg "/sdcard/Download/qr_test.png" --es k elder-adb --include-stopped-packages
→ data="qr:http://127.0.0.1:8898/api/report?k=6e761d0b34b5"
```

即：**相机能开、照片能写、码能解**。剩下唯一没验证的是「真实场景拍照能不能对准」，
需要你拿中继网页上那个二维码实扫一次。

### 新增排障命令

```
provision.ps1 里没有对应参数，直接发广播：
am broadcast -a com.elder.launcher.ADMIN --es cmd qrdecode --es arg "/sdcard/Download/xx.png" --es k elder-adb --include-stopped-packages
```

扫不上时，可以让家人把二维码截图发到手机，用这条命令判断是「拍不清楚」还是「解码器坏了」。

### 顺带说明

- 上一节记的「域名解析不了」又偶发过一次（12:39），但随后连续两次都是
  `HTTP 401 令牌不对`（说明解析正常）。判断是 WIFI 刚重连时 DNS 还没就绪的瞬时问题，
  不是稳定故障；`ReportUploader` 会把这期间的报文入队，网络好了自动补发。

## 十、第二轮（两台手机）：同步、扫码、日志乱码

两台机器：荣耀10 `COL-AL10`（只装家人端）／荣耀 Magic2 `TNY-AL00`（只装老人端，WIFI `FF`，192.168.6.x）。
NAS 在光猫下一级、手机在路由器下一级，不同网段 —— 正好覆盖"手机到 NAS 要过一层"的真实情况。

### 10.1 电脑端日志乱码（已修）

根因：`provision.ps1` 上一轮改成按 UTF-8 写输出（为了修控制台乱码），但电脑端 GUI 的
「一键部署」是在 **Start-Job 的子进程** 里读它，子进程默认按 GBK 解码 → 整段乱码。
应用管理那条路用的是 ProcessStartInfo，同样没指定编码。

三处一起改：
1. 主进程 `[Console]::OutputEncoding = UTF8`（`& adb` 直接输出也受用）
2. `Start-Job` 加 `-InitializationScript { [Console]::OutputEncoding = UTF8 }`
3. `ProcessStartInfo` 加 `StandardOutputEncoding/StandardErrorEncoding = UTF8`

验证：同一个 `provision.ps1 -Info`，默认解码出「璁惧锛欳OL-AL10」，设成 UTF-8 后是「设备：COL-AL10」。

### 10.2 扫一扫：解码器偏弱，不是拍不清

用中继同款二维码做了 9 种退化，用 App 自己的解码器逐个试（新增 `qrdecode` 命令）：

| 样本 | 2.9.4（单轮解码） | 2.10.2（多轮） |
|---|---|---|
| 原图 / 旋转 90° / 旋转 180° | ✅ | ✅ |
| 模糊 r=2 / r=4 | ✅ | ✅ |
| 缩到 187px | ✅ | ✅ |
| **深底反色二维码** | ❌ no-qr | ✅ |
| 白底 JPEG q30–q90 | — | ✅ 全通过 |
| **深底+噪点+模糊+JPEG q30**（最接近真机） | ❌ | ❌ |

结论：单轮解码器**刚好卡在真实照片的边缘**，所以"扫几十次中一次"。
2.10.2 起加：`TRY_HARDER` + `ALSO_INVERTED`（修好反色码）+ 全局直方图二值化 +
中间 70% 裁剪 + 对比度拉伸，四种组合依次尝试。

另外两处：
- 自家生成的二维码静区从 1 个模块改成标准 4 个（贴在深色页面上没有白边时，相机很难定位）
- 「扫一扫」旁边加了**「从相册选一张二维码截图」**：截图是 PNG、无压缩噪声，
  实测一定能解 —— 家人把二维码截图发到老人机，比对着屏幕拍靠谱得多

### 10.3 中继没有 CORS：家人端的中继模式一直是全废的（已修）

家人端页面是 `file:///android_asset/index.html` 加载的，跨域请求中继时浏览器会拦。
中继**一个 CORS 头都没有** → WebView 里所有中继请求都是 `Failed to fetch`。

也就是说：中继模式下的「查询位置」「围栏同步」「拉取轨迹」「远程命令」**其实从来没通过**，
你之前看到的红字「连不上老人机」正是这个链条断掉的表象之一。

两端都补：
1. 中继加 CORS（`Access-Control-Allow-Origin: *` + OPTIONS 预检 204）。鉴权靠 URL 令牌、
   不靠 Cookie，放开 * 没有额外风险。
2. 家人端 WebView 开 `setAllowUniversalAccessFromFileURLs(true)`（file:// 页面跨域必需）。

实测（荣耀10，中继模式）：修之前卡片显示「还没查过位置」、点查询报
`连不上中继：Failed to fetch`；修之后卡片显示「上次 10-28 14:44　30 米 / 64% · WiFi · 轨迹 22 点」，
点查询显示「来自中继 · 11 分钟前」+ 时间/精度/电量/坐标 + 地图打点，红字消失。

### 10.4 轨迹点用 `lng`、中继只认 `lon` → 经度全是 0（已修）

`TrackStore.add()` 写的是 `"lng"`，中继 `Point` 只解 `json:"lon"`，
而中继判定位置时**优先用轨迹点** → 只要手机动过，位置就会变成 (34.07, 0)，
家人端地图画到本初子午线，围栏距离全部错。

修：
- 老人端轨迹点同时写 `lon` 和 `lng`，读旧数据时把 `lng` 补成 `lon`
- 中继 `Point` 增加 `Lng` 字段并在解析后 `normalizeLng()`，两个键都认
- 单测 `TestTrackAcceptsLngKey` 覆盖老格式/新格式/pos 三种

实测：修之前 `lat=39.90061, lon=0`；修之后 `39.90061, 116.394248`。

### 10.5 「查询位置」在中继模式下还去直连老人机（已修）

`query()` 不分模式，永远 `fetch http://<host>:8899/loc`。中继模式下 host 是空/不可达，
必然失败，然后弹红字「连不上老人机」—— 而中继明明显示在线，家人就被这句话误导了。

现在按模式分流：中继模式只问 `/api/status`，结果上方标「来自中继 · N 分钟前」，
超过 30 分钟标红「可能断网了」，并显示排队中的命令数。

### 10.6 新增「催一次定位」：定位也能近实时

链路：家人点「催一次定位」→ 中继排队 `locate` → 老人端下次上报取走 → 立即 `getOnce(15s)`
→ 更新缓存 → **立刻补发一次上报**（不等 10 分钟周期）→ 家人下次刷新就能看到新位置。

实测（本地中继）：
```
POST /api/cmd {"cmd":"locate"} → 入队
触发一次上报 → 21 秒后 status 里：
  cmdResult = {"cmd":"locate","ok":true,"msg":"刚定的新位置，精度 30 米"}
  posT 已更新，pendingCmds=0
```

⚠️ **NAS 上的中继还是 1.6.1，不认识 `locate`**，会回「不支持的命令：locate」。
要这个功能必须升到 `dist/elderrelay-1.6.2.fpk`。

### 10.7 「老人端是不是一直在连着中继？」

不是。现在只有一条单向通道：**老人端每 10 分钟 POST 一次**（`/api/report`），
命令搭在这次响应里捎回去（1.6.1 起只随实时上报捎，避免被补发吞掉）。
所以：

- 中继显示「在线」= 最近 90 分钟内收到过上报（`OfflineMinutes`），**不代表有连接**
- 家人直连老人机需要老人机有公网入口 + 端口开着，内网/CGNAT 下必然失败 ——
  这就是红字「连不上老人机」的由来；中继模式根本不该去连它（10.5 已修）
- 命令的天然延迟 = 一个上报周期（默认 10 分钟）。「催一次定位」把后半程（执行→回报）
  压到了秒级，但前半程（下发）仍要等下一次上报

要压到秒级，只有让老人端**持续保持连接**（长轮询）或建隧道，代价是常驻连接耗电、
移动网 NAT 超时后要重连、熄屏被系统冻结等。可选的折中：
- 只在**充电时**开长轮询（老人在家最可能插着电）
- 或把上报周期从 10 分钟调到 3–5 分钟（耗电与流量都可接受，实现成本为零）

这次没做长轮询，先把「误报连不上」和「催一次」做掉；要不要上长轮询，看你实际使用感受。

## 十一、第三轮：CF 隧道接通后的秒级响应

这次的环境变了：中继通过 **Cloudflare 隧道** `https://uug.dpdns.org/` 暴露到 IPv4，
老人端用移动数据也能直连（之前只有 IPv6 域名，移动网时好时坏）。

### 11.1 「升级到 1.6.2 但网页显示 1.6.1」

**升级是成功的，是版本号写错了。** `main.go` 里 `const Version = "1.6.1"` 我上次只改了
fpk manifest、忘了改这个常量，所以二进制是 1.6.2 的能力、自报 1.6.1。

已修：版本号以源码常量为唯一来源，`/api/health` 也跟着它走。现在 1.7.0。

顺带一个教训：以后判断"线上跑的是不是新包"，别看版本号，看能力 ——
直接打 `POST /api/cmd {"cmd":"locate"}`，回「不支持的命令」就是旧包。

### 11.2 「催一次定位没下发」——其实下发了，只是要等一个上报周期

实测：排队 `locate` → 手动触发一次上报 → 25 秒后 `cmdResult` 回来「刚定的新位置，精度 30 米」。
**机制是通的**，问题是：

1. 命令只在"老人端下一次上报"时才捎走 —— 默认 10 分钟，人早就以为没反应了
2. 走 CF 隧道时**冷启动握手很慢**：实测第一次上报在 20 秒时超时失败，紧接着第二次成功。
   而老人端原来的 `CONNECT_TIMEOUT` 只有 8 秒，必挂 → 上报进补发队列 → 再等下一个 10 分钟

已修：
- 连接超时 8s → **20s**，读超时 15s → **25s**
- 新增**快通道**（下节）

### 11.3 快通道：命令 2 秒到

老人端开一条长轮询：

```
GET /api/wait?k=<设备令牌>&t=25   ← 老人端挂着
    中继一有命令立刻返回 {"cmd":{...}}
    没命令就返回 {"cmd":null}，老人端马上再挂一次
```

中继侧 `pushCmd()` 入队后 `broadcast()` 唤醒所有挂着的长轮询。
整条链路都是**老人端主动发起**，不需要公网入站、不需要端口映射，穿 NAT / CF 隧道都能用。

实测（本地中继 + adb 端口映射，全程不手动触发上报）：

```
20:15:59  POST /api/cmd {"cmd":"locate"} → id=c4ab976dbce
20:16:01  [2s] cmdResult = 刚定的新位置，精度 30 米，pendingCmds=0
```

**2 秒**。代价是每 25 秒一次心跳（约 3–4 MB/天，耗电略增），所以做成可关：
设置 → 定位和传输 → 「秒级响应（家人查询几秒内到）」，
或管理命令 `fastlink on|off`；电量 ≤10% 且没充电时自动暂停。

⚠️ **必须把中继升到 1.7.0**：1.6.2 没有 `/api/wait`，老人端会一直 404 然后退避重试
（不影响普通上报，但没有秒级响应）。

### 11.4 家人端按钮「按了没效果」

查到两个原因，都不是按钮坏了：

1. 那台手机上**一条老人都没配**（重装后 localStorage 空），点「高德打开」只会弹
   "先查一次位置"，而这个 toast 很容易被忽略 → 看起来像没反应
2. 外部打开失败时（没浏览器/被拦）走的是 `window.open`，在 WebView 里**静默失败**

已修：
- 没位置 → 先提示「还没有位置，正在查…」并自动查一次
- 外部打开失败 → 复制高德链接到剪贴板 + 明确提示
- 「看大地图」以前和「高德打开」共用同一个函数（等于没用），现在真的滚到地图并放大

### 11.5 中继直接托管家人页（`/f`）

家人页就是一份 68KB 的 `index.html`，没必要重写第二套。构建时把它复制进中继
（`relay/web/family.html`，`go:embed` 打包），中继在 `/f` 直接提供：

```
https://uug.dpdns.org/f?k=<设备令牌>&n=magic2
```

带 `k` 时把设备写进浏览器本地存储，页面就当成"已添加这位老人"，随后清掉地址栏参数。
这样在飞牛 APP 里点一下就能看老人，不用再装 App，也**不会出现网页版功能落后一截**的分叉。

分工：`/f` = 家人视角（第一页），`/` = 管理台（设备/令牌/围栏/配置，第二页）。

⚠️ 安全边界：`/f` 用 URL 里的令牌鉴权，和上报地址同级别 —— 谁拿到链接谁就能看这位老人的位置。
要更严可以再套 Basic 密码，但飞牛 APP 里每次输密码体验很差，暂时没套。
