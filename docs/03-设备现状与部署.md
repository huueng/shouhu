## 四、华为 / 荣耀的关键结论

1. **第三方桌面被系统拒绝**
   - `adb shell cmd package set-home-activity com.elder.launcher/.MainLauncherActivity`
     → `Error: Failed to set default home.`
   - 系统日志根因：`Component {...MainLauncherActivity} not allowed to be default home on user 0`
   - 系统「设置 → 桌面」页面里**只列出华为桌面**，本应用根本不出现
   - 对照试验：`set-home-activity` 指向华为桌面 → `Success`，说明是"候选资格"被拦，不是命令本身不可用
   - 试过加 `android:directBootAware="true"`、先启动 App 再设、`--user 0`，均无效
   - **结论：归档文档里"EMUI 必须用 ADB 设默认桌面"这条经验在当前系统版本已失效**

2. **替代方案：锁定任务（LockTask）**
   实测有效——开启后 HOME 键会被系统直接吞掉，老人退不出去，接管效果与"默认桌面"等价。
   代价：需要 Device Owner；开机后要靠 `BootReceiver` 拉起。

3. 状态栏：锁定任务开启时由 DO 禁用；不开时正常显示（2.0 已改为跟随开关）。

## 五、日常部署（三种方式）

### 方式 A：一键脚本（推荐）

```powershell
# 只看状态
powershell -ExecutionPolicy Bypass -File tools\provision.ps1 -Check

# 全新机全流程：安装 + 激活 Device Owner + 授权 + 设桌面
powershell -ExecutionPolicy Bypass -File tools\provision.ps1 -All

# 已激活过的机器：只补权限（不会碰 Device Owner）
powershell -ExecutionPolicy Bypass -File tools\provision.ps1 -Permissions
```

也可以双击 `tools\deploy.bat`（默认跑 `-Check`）。

### 方式 B：手动命令（脚本内部的等价操作）

```bash
adb install -r elder-guardian/app/build/outputs/apk/release/app-release.apk
adb shell dpm set-device-owner com.elder.launcher/.ElderDeviceAdminReceiver
adb shell pm grant com.elder.launcher android.permission.CALL_PHONE
adb shell cmd appops set com.elder.launcher SYSTEM_ALERT_WINDOW allow
adb shell cmd appops set com.elder.launcher GET_USAGE_STATS allow
adb shell settings put secure enabled_accessibility_services com.elder.launcher/com.elder.launcher.ElderAccessibilityService
adb shell settings put secure accessibility_enabled 1
adb shell cmd notification allow_listener com.elder.launcher/com.elder.launcher.ElderNotificationListener
adb shell dumpsys deviceidle whitelist +com.elder.launcher
```

> Device Owner 只能在 **未登录任何账号、未设锁屏密码** 的机器上激活，且**不可撤销**。
> 脚本已内置前置判断，若机器不满足条件会直接提示，不会装到一半失败。

### 方式 C：手机上自己点

`老人守护 → 标题连点 8 次 → 守护自检`，9 项逐条看，能点「去开启」的直接跳系统设置。

## 六、应急解锁

```powershell
powershell -ExecutionPolicy Bypass -File tools\provision.ps1 -Unlock
```

等价手动命令（**会移除 Device Owner，之后需恢复出厂才能重新激活**）：

```bash
adb shell am force-stop com.elder.launcher
adb shell dpm remove-active-admin com.elder.launcher/.ElderDeviceAdminReceiver
```

如果只是被屏幕固定困住、不想动 Device Owner：

- 长按标题 5 秒 → 点「解除」，或在设置页点「立即解除屏幕固定」
- 手机不在身边：`adb shell am force-stop com.elder.launcher` 通常也能解开（锁定任务下可能无效，此时只能靠上面两条）

设备日志同时给出证据：

```
ElderLocateSrv: 监听成功：IPv6 [::]:8899
```

`EADDRINUSE` 是好事：说明 `[::]` 是双栈套接字，已经把 IPv4 一起接管了，不需要再开一个。

**顺带修掉**：开机时无条件启动悬浮导航键，导致屏幕右下角一直浮着三个圆点挡住卡片。
现在改为 `floating_nav` 开关控制（默认关），设置页「常用」里可开关。

### 2026-10-26 11:57 · 电话页 BUG（锁定任务白名单）

用户反馈：来电不进通话页、去电也不出通话页，但通话本身是通的。

根因：`dumpsys activity` 显示 `mLockTaskModeState=LOCKED`，而 `buildLockTaskPackages()`
只放了 `com.android.phone` / `com.android.contacts` / 拨号器，**没有放真正画通话界面的
`com.android.incallui` 和 `com.android.server.telecom`**。锁定任务下非白名单包无法启动 Activity，
于是"通话建立、界面不出现"。

修复后实测：

```
adb shell am start -a android.intent.action.CALL -d tel:10086
→ mResumedActivity: com.android.incallui/.InCallActivity
→ 日志：Device Owner 限制已按配置下发，锁定任务白名单 21 个
```

> 注意：这条只在**锁定任务打开时**才会暴露；关掉锁定任务电话页一直是正常的，
> 所以之前几轮验证都没发现。
