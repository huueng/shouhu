# 中继 1.10.0：命令秒回、快照可命名、围栏能画出来

这一轮全部集中在**中继**（老人端顺带到 2.12）。家人端 App 没动。

版本：中继 **1.10.0** / 老人端 **2.12**（code 28）/ 家人端仍是 2.8

---

## 一、「健康检测没反应」到底卡在哪

三层原因叠在一起，缺一层都不会是这个现象：

### 1. 命令只能"等下一次上报"捎走

1.9.0 的命令通道是：家人 `POST /api/cmd` → 入队 → **老人端下一次上报时**，中继把命令塞在响应里。
老人端上报周期当时是 10–15 分钟，你点完等 1 分钟没动静，看起来就是"没发出去"。

### 2. 老人机的快通道没在跑

`FastLinkService`（秒级通道）只在**改设置或开机**时被拉起。装完新版本、被华为清掉常驻服务之后，
它就一直是停着的 —— 你手机上实测 `dumpsys activity services` 里只有 `DdnsService`，没有它。
所以即使 1.9.0 已经有 `/api/wait`，也没人挂在那条长连接上。

### 3. 页面只能写死"最多 10 分钟"

中继没告诉页面"老人端到底连着没有"，于是文案永远是"等下次上报（最多 10 分钟）"，
你没法判断是慢还是坏了。而连点 20 次就真的排了 20 条（没有任何去重），
`pendingCmds=20` 更是把人往"卡死了"上带。

### 实测（用你的真实中继 + 新老人端）

```
22:06:34  POST https://shouhu.example.com:812/api/cmd {"cmd":"health"}
22:06:37  [3s] pendingCmds=0
          cmdResult = health True 「4/10 正常；缺：设备所有者、无障碍服务、…」
```

**3 秒**。同样的命令在改之前是要等一个上报周期的。

## 二、这次改了什么

### 2.1 命令去重 + 可清空

- 同一设备、同一条命令（含参数）在队列里还没被取走时，**再点不再入队**，直接回"已经在队列里了"
- 响应里带上 `dup / fastLink / pending / interval`，页面据此说人话
- 新增 `POST /api/cmd/clear?k=令牌`：一键清空排队命令（页面上的「清空排队（N）」）

实测：断掉快通道后连点 5 次健康检测 → 队列 **1 条**，后 4 次都回 `dup=true`；清空后 `pending=0`。

### 2.2 `/api/status` 多了三个字段

| 字段 | 含义 | 家人页怎么用 |
|---|---|---|
| `fastLink` | 现在有没有 `/api/wait` 挂着 | 显示"秒级通道已连接 / 未连接" |
| `snaps` | 老人机上现有快照列表（id/名字/时间） | 「恢复布局」的列表 |
| `intervalMin` | 老人端当前上报周期 | "等下次上报（约 N 分钟）"，不再写死 10 |

`fastLink` 用**连接条数**而不是布尔：切网时可能同时挂着两条，布尔会被先结束的那条清零，
显示成"未连接"，家人就误以为要等 10 分钟。

### 2.3 围栏不显示：两个 bug 叠着

| 位置 | 问题 |
|---|---|
| 中继 `/api/status` | 围栏只输出 `lon` |
| 家人页画图 | 读的是 `f.lng` → `undefined` → 圆算成 `NaN` → Leaflet 直接不画 |

所以"加了围栏地图上没反应"跟地图服务无关，是字段名对不上。现在两端都补：
中继同时给 `lon` 和 `lng`，页面再做一次归一（老数据也救回来）。

### 2.4 `Invalid LatLng object: (39.900622, undefined)`

你截图里那条红字不是网络问题。`mapPt()` 原来只要 `gcj_lat` 有值就直接
`return [gcj_lat, gcj_lng]` —— 老数据里 `gcj_lng` 缺失时就把 `undefined` 交给 Leaflet，
抛出的异常又被 `queryViaRelay` 的 `.catch` 兜成「连不上中继」，把人往网络问题上带。

现在 `mapPt` 三个分支都会校验：能算就转 GCJ，算不出返回 `null`（不画这个点），
同时把"取数失败"和"画图失败"分开提示。单测（Node）覆盖：

```
围栏只有 lon        → 归一成 lng，画圆坐标 [39.899359, 116.399857] 有效
点只有 gcj_lat      → null（不再抛异常）
点只有 lon          → [39.898748, 116.399608]
空点                → null
```

### 2.5 存快照可命名、恢复布局能挑历史

老人端 `SnapshotStore` 重写：

- `save` 带参数就是名字（页面会弹输入框，默认「手工 11-10 22:15」）
- 快照列表（`snaps`）随每次上报带给中继，家人页直接列出来
- `restore` 的 `arg` 就是快照 id：`first`（首次基线）/ `manual`（旧版手动）/ `s<时间戳>`（具名）
- 新增 `snapdel` 删掉某一份；首次基线不给删（那是安全网）
- 最多留 20 份具名快照，超了自动淘汰最老的

**恢复时保留上报地址**——这条很关键。快照是几周前存的，里面的令牌早换了，
以前恢复完手机当场失联，还以为"恢复功能坏了"。实测：

```
restore first → 「已恢复到「首次装机基线」，14 项配置（上报地址保持不变）」
info url    → http://127.0.0.1:8898/api/report?k=... （没被冲掉）
```

### 2.6 快通道现在会自己回来

之前只在上报排期（`schedule()`）里拉一次。现在三处都保：

1. 每次定时上报的心跳里确认一次（`ReportReceiver`）
2. 任何一次上报动作前确认一次（`uploadAsync`）
3. 开机广播里按上报开关重新排期（`BootReceiver`）

装完新版本 / 被系统清掉之后，最迟一个上报周期内自己连上。

## 三、部署

1. 飞牛里换 `elderrelay-1.10.0.fpk`，覆盖安装
   - 装完 `https://shouhu.example.com:812/api/health` 应显示 `"version":"1.10.0"`
2. 老人端装 `elder-guardian-2.12-release.apk`（exe 里已内置）
3. 家人页刷新（中继重启后页面代码也跟着换了）

### 你手机上还有一个问题：Device Owner 掉了

实测 `dumpsys device_policy` 里 **一个设备管理应用都没有**，健康检测也因此只有 4/10：

```
缺：设备所有者、无障碍服务、通知使用权、悬浮窗权限、使用情况访问、电池优化白名单
```

没有 Device Owner，锁定任务（不让老人退出桌面）是不生效的。恢复办法：

```
tools\provision.ps1 -All -Serial <序列号>
```

`-All` 会重新 `dpm set-device-owner`。如果失败（手机已登录华为账号或设了锁屏密码），
按脚本提示得恢复出厂后跳过账号登录再激活。
