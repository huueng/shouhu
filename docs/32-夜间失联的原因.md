# 夜里"老人端失联"是怎么回事

## 现象

早上起来看家人页，显示「超过 30 分钟没更新，可能断网了」，位置停在半夜。

轨迹点时间戳里能直接看到：

```
11-11 21:44 → 22:13   28 分钟
11-12 00:06 → 11:10   664 分钟（11 小时）
```

## 不是断网，是手机睡着了

中继和网络都正常。真正的原因是**上报用的闹钟不会唤醒设备**：

```java
// 老人端 2.15 及以前
am.setInexactRepeating(AlarmManager.ELAPSED_REALTIME,
        now + 30_000, interval, pi);
```

`ELAPSED_REALTIME` 是**非唤醒**闹钟。手机深度睡眠时它根本不触发，只会等下一次被
别的事情（来电、充电、用户点亮屏幕）唤醒时补一次 —— 夜里没人动手机，于是一整夜都没有上报。

`dumpsys alarm` 里的证据：

```
ELAPSED #1: Alarm{...}
  tag=*alarm*:com.elder.launcher.REPORT_TICK
  type=3      wakeup=false        ← 关键
  window=+7m30s0ms repeatInterval=600000
```

对比轨迹采样的闹钟（那个是唤醒型）：

```
ELAPSED_WAKEUP #2: ...
  tag=*walarm*:com.elder.launcher.TRACK_TICK
  type=2      wakeup=true
```

## 改法（老人端 2.16）

```java
am.setExactAndAllowWhileIdle(AlarmManager.ELAPSED_REALTIME_WAKEUP, next, pi);
```

- `_WAKEUP`：真的把设备叫醒
- `setExactAndAllowWhileIdle`：Doze 里也能触发（系统限速最快 9 分钟一次，我们设 10 分钟）
- 精确闹钟**不会自己重复**，所以每次触发后重新排一次（`ReportReceiver` 一进来就先排下一次，
  万一这次上报崩了，闹钟也不会断）

装完在手机上核对：

```
ELAPSED_WAKEUP #0: Alarm{...}
  tag=*walarm*:com.elder.launcher.REPORT_TICK
  type=2      wakeup=true
  window=0    repeatInterval=0        ← 精确闹钟
```

日志：`主动上报已排期：唤醒型精确闹钟，每 10 分钟`

## 代价

每 10 分钟唤醒一次，一夜 8 小时约 48 次，每次只发一个几 KB 的 POST。
实际耗电通常在 1%–3%（他这台已经在电池优化白名单里）。

## 还有一层：厂商省电

华为/荣耀的「应用启动管理」比 AOSP 更凶，必要时会把进程整个冻住，
连唤醒型闹钟也可能被吞。建议在老人机上看一眼：

- 设置 → 电池 → 启动管理 → 守护桌面：关掉「自动管理」，改成手动，允许自启动/关联启动/后台活动
- 设置 → 电池 → 更多电池设置 → 休眠时始终保持网络连接：打开

这两项 device owner 也改不了（是厂商私有设置），需要手动点一次。

## 顺带改的文案

家人页原来只要超过 30 分钟没更新就写「可能断网了」，把人往网络问题上带。
现在写「可能手机息屏没上报，或者网络断了」，并且夜里这种情况会自己恢复，
不用去查路由器。
