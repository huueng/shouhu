# 中继 1.11.0：拉取轨迹修好、体检看得更细、能远程调声音

版本：中继 **1.11.0** / 老人端 **2.13**（code 29）/ 家人端仍是 2.8

---

## 一、「拉取轨迹」为什么点了没反应

你看到的那条报错已经把原因写全了：

```
连不上：Failed to execute 'fetch' on 'Window':
Failed to parse URL from http://:8899/track?key=
```

`loadTrack()` 从来没分过模式，永远是 `apiUrl(e).replace('/loc?', '/track?')` ——
也就是拼成 `http://<host>:8899/track?key=…`，那是**直连老人机**的老方案。
中继模式下 `host` 是空的，URL 变 `http://:8899/...`，浏览器当场解析失败。

而"每次打开自动拉取"走的是 `syncElderRelay()`，那是另一条路（`/api/status` + `/api/track`），
所以自动更新一直正常 —— 正好把按钮的问题掩盖了。

现在按钮按模式分流：中继模式走 `GET /api/track?k=…&since=<上次的点>`，
只取增量，合并后提示"合并了 N 个点"或"没有新的轨迹点（中继上共 N 个）"。

## 二、体检：从"两行"变成一屏

以前中继只解析电量、充电、网络这几个字段，其余全丢 —— 所以家人端点「体检」，
永远只有"电量 / 网络"两行。现在 `/api/status` 按白名单把老人端状态**原样透出**：

| 显示 | 来源 | 为什么值得看 |
|---|---|---|
| 音量：铃声 10/15、媒体 5/15 | `ringVolume / volMusic` | 老人常把媒体音量按到 0（看视频听不见），铃声 0 则接不到电话，分开显示才分得清 |
| 静音模式 / 振动 | `ringerMode` | 同上，是系统级静音而不是某个流调零 |
| 电池 36.5℃ | `battTemp` | 常年插着充电器，发热/鼓包能提前看出来（≥42℃ 标红） |
| 可用内存 900 MB | `memFreeMB / memLow` | "手机变卡"最常见的原因 |
| 已开机 3 天 5 小时 | `uptimeMin` | 超过 7 天提示"很久没重启" |
| 剩余存储 41 GB | `storageFreeMB` | 低于 1 GB 标红 |
| 屏幕亮/灭、已锁 | `screenOn / locked` | 判断"人是不是在用" |

**这些都不额外耗电**：全部是读一次就返回的系统接口（`AudioManager.getStreamVolume`、
`StatFs`、`ActivityManager.MemoryInfo`、`SystemClock.elapsedRealtime`、电池的 sticky 广播），
不开传感器、不唤醒设备、不申请新的后台任务。唯一新增的权限是
`MODIFY_AUDIO_SETTINGS`（normal 级，安装即授予），那是调音量用的。

## 三、健康检测：正常的也列出来

以前只有 `4/10 正常；缺：设备所有者、无障碍服务、…` —— 看到 10/10 反而不知道查了什么。
现在：

```
8/10 正常
正常：锁定任务、无障碍服务、通知使用权、悬浮窗权限、使用情况访问、定位、主动上报、网络
缺少：
· 设备所有者：未激活（锁定、禁装禁卸不可用）
· 电池优化白名单：未加入（定时上报可能延迟）
```

家人页会把换行渲染出来（以前多行 msg 会挤成一行）。

## 四、远程调声音

新命令 `volume`，参数：

| 参数 | 作用 |
|---|---|
| `up` / `down` | 媒体音量 ±1 格（自动按满格数换算） |
| `mute` | 媒体音量归零（看视频没声音时反过来"确认是不是静音了"） |
| `unmute` | 恢复到满格的一半 |
| `set:0-100` | 按百分比设 |
| `ring:up` / `ring:mute` / `ring:set:60` | 加 `ring:` 前缀就是调**铃声** |

家人页在体检区下面加了四个按钮：`音量 − / 音量 + / 静音 / 恢复声音`。
执行结果显示成 `已设置媒体音量 5 → 4/15`，改完顺手刷新体检（音量行会跟着变）。

实现走系统 `setStreamVolume`，不碰勿扰白名单、不改系统设置；权限不够会明确回
`系统不让改音量（缺权限或被系统策略限制）`，不会假装成功。

实测：

```
volume down → 已设置媒体音量 5 → 4/15
volume up×3 → 已设置媒体音量 6 → 7/15
```

## 五、秒级通道可以远程开关

体检区新增一行按钮，文案跟着实际状态走：

```
秒级通道：已连接（点击关闭）   /   秒级通道：未连接（点击开启）
```

对应命令 `fastlink on|off`。两个方向都能用，但要注意：

- **关掉是立刻生效的**（长轮询马上断）
- **再打开要等下一次上报**（没有连接时命令只能随上报捎过去），页面会提示
  "老人端没挂着连接，等下次上报（约 10 分钟）"

这也顺便回答了"中继能不能控制老人端"——能，只是关掉之后失去秒级通道，
重新打开必然要走一次周期上报。要不要在关掉时顺便触发一次立即上报，看实际使用再定。

## 七、部署与验证

1. 飞牛换 `elderrelay-1.11.0.fpk`，装完 `/api/health` 显示 `1.11.0`
2. 老人端装 `elder-guardian-2.13-release.apk`（exe 里已内置）
3. 验证顺序：
   - 点「拉取轨迹」→ 应该提示"合并了 N 个点"，不再报 `Failed to parse URL`
   - 点「体检」→ 应该看到音量、电池温度、可用内存、开机时长、存储
   - 点「健康检测」→ 多行，正常项和缺少项都列出来
   - 点「音量 −」→ 老人机声音真的变小，按钮下方显示 `5 → 4/15`
   - 点「秒级通道：已连接」→ 确认关掉；再点开启，等一次上报后恢复
   - 「恢复布局」→ 每行点「查看」，能读到配置摘要

> 中继必须是 1.11.0：1.10.0 及以前不认识 `volume / fastlink / snapshow`，
> 会回「不支持的命令」；体检的那些字段也是 1.11.0 才开始透出来的。
