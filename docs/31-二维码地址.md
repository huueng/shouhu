# 二维码里到底该写哪个地址

## 问题

以前二维码是拿"你打开这个页面时用的地址"生成的：

```go
base := baseURL(r)   // scheme + r.Host
```

可是同一个中继会被三种方式打开，Host 完全不一样：

| 打开方式 | 地址 | 码里的地址 | 扫了会怎样 |
|---|---|---|---|
| 飞牛图标 / 网关 | `https://<飞牛域名>/app/elderrelay` | `https://<飞牛域名>/api/report` | **打不通** —— 中继的接口不在域名根上 |
| 局域网 | `http://192.168.1.10:8898` | 同一个局域网地址 | 在家能用，**出门就废** |
| DDNS 域名 | `https://shouhu.xxx.com:812` | 同一个域名 | ✅ 到哪都能用 |

而页面上没有任何提示，所以"扫出来能不能用"完全取决于你当时怎么打开的 ——
这就是你发现的"飞牛图标进去扫的码没法用、局域网进去扫的码只能在家用"。

## 做法：把地址变成配置，而不是访问方式的副产品

新增一个配置 `public_base`（页面里叫「二维码地址」/ 对外地址）。

规则很简单：

```
配了 public_base       → 所有二维码和上报地址都用它，不管你从哪进
没配 + 从飞牛网关进     → 不生成二维码（生成了也是废的），提示你去填
没配 + 从局域网进       → 生成二维码，但明确标「局域网地址 · 只能在家用」
没配 + 从域名进         → 生成二维码，标「外网可访问」，并建议保存下来
```

设备页顶部因此多了一张卡：

```
二维码地址                     决定扫码后能不能用

现在用   https://shouhu.example.com:812   外网可访问
         [ https://shouhu.example.com:812 ]  [保存]  [用当前访问地址]

二维码和上报地址都用它。改了之后，老人端和家人端要重新扫一次才会换到新地址。
```

网关进来没配时是这样的：

```
现在用   还不知道   通过飞牛图标进来时，浏览器地址是「飞牛域名 + /app/elderrelay」，
                    那不是中继的对外入口
         [ 填写对外地址 ]  [保存]
填一个能从外网访问的地址（DDNS 域名或反向代理，例如 https://shouhu.xxx.com:8898），
保存后这里才会出二维码。不填也能用：家人端手动添加、老人端手填地址都行，只是没法扫码。
```

## 为什么不用"当前访问地址猜一下"

想过几种更"聪明"的做法，都不行：

- **从 Host 猜**：网关下 Host 是飞牛域名，端口也是飞牛的端口，猜出来必错。
- **问飞牛的 DDNS 配置**：应用拿不到，而且用户可能用的是自己的域名 / CF 隧道。
- **让二维码里只放令牌，家人端自己去探测地址**：家人端在外面，探测不到内网；
  探测域名需要先知道域名 —— 绕回去了。

地址是**部署信息**，只有部署的人知道。所以做成一次性配置，配一次，之后
不管从哪个入口打开、不管换手机还是换浏览器，码里都是同一个地址。

## 怎么配

1. 中继升到 **1.14.0**，打开设备页
2. 「二维码地址」卡里填你的对外地址，例如：
   - DDNS：`https://shouhu.example.com:812`
   - Cloudflare 隧道：`https://uug.dpdns.org`
   - 反向代理：`https://shouhu.example.com`（80/443 就不用写端口）
3. 保存 → 页面刷新 → 二维码出现，标「外网可访问」
4. 让老人端和家人端重新扫一次

也可以直接改 `config.json`：

```json
{ "public_base": "https://shouhu.example.com:812" }
```

## 注意

- 改了这个地址，**老人端要重新扫码/改地址**，否则它还往旧地址上报；家人端也一样。
- 它不影响中继监听在哪个端口、也不影响网关入口 —— 只是"二维码里写什么"。
- 局域网地址不会被拦，只是标出来"只能在家用"。有些人本来就没打算在外网用。
