# 20 · 电量显示与顶部状态区实测（2.6）

> 真机：荣耀 COL-AL10（EMUI 10，1080×2280，density 480 → 1dp = 3px）
> 时间：2026-10-27，插着 USB 充电，WIFI 名为 `FF`

## 一、"电量不准"其实是两件事

### 1. 老人端自己冻住了（真 bug）

实测：系统 `dumpsys battery` = **75%**，桌面却显示 **38%**。

原因在生命周期：

```
onCreate → setupStatusViews() → registerBattery()   // 只在这里注册一次
onPause  → unregisterBattery()                      // 一离开桌面就注销
onResume → （什么都没做）                            // 回来不重新注册
```

只要点开过任何一个应用再回到桌面，电量就永远停在离开那一刻的值，信号监听同理。

**修法**：注册搬到 `onResume` 的 `startStatusListeners()` 里，`onPause` 照旧注销。
每次回桌面都会重新读一次 sticky 广播，屏幕上的电量和系统状态栏始终一致。

### 2. 家人端看到的是"上报那一刻"的值（不是 bug，是口径）

老人端每 10 分钟上报一次，中继落库的是那一次的 `battery`。
如果手机在充电，十分钟就能差 1～2%；如果上报一直失败，家人端看到的就是几小时前的值。

**修法**（不改上报频率，把话说清楚）：

- 老人端 `StatusReport` 增加 `batteryT`（采样时刻），电量优先取
  `ACTION_BATTERY_CHANGED` 的 sticky 广播（和系统状态栏同源），读不到再退回
  `BatteryManager.BATTERY_PROPERTY_CAPACITY`。
- 中继 `Report` 增加 `BatteryT`：报文带了电量就记这一包的时间；没带就**跟着沿用**上次的
  时间（不能只沿用数值，否则旧电量会被标成刚测的）。`/api/status` 输出 `batteryT`。
- 家人端体检显示「电量 73%（16:40 测，3 分钟前）」；卡片上超过 30 分钟没更新就加「·旧」。
- 家人端「体检」原来不分模式，中继用户点开永远"连不上老人机"（拿 `host:port` 去连）。
  现在中继模式改走 `/api/status`，末尾还会标「以上来自中继，最后上报 X（X 分钟前）· 在线/已失联」。

## 二、顶部四个触摸区（改前改后）

实测用 `uiautomator dump` 取到的真实 bounds：

| 区域 | 改前 | 改后 | 点一下 |
|---|---|---|---|
| 时间 | 118×54dp（只有大字可点） | **137×101dp**（时间+日期+农历整块） | 念时间；连点 8 次进设置；长按解除 |
| 电量 | 68×90dp | 68×90dp（本来够大） | 念电量 |
| 天气 | 103×40dp（只有温度可点） | **103×63dp**（温度+天气词整块） | 念天气 |
| 信号/网络 | **42×21dp**（几乎点不中） | **58×48dp**（补 minHeight/minWidth + padding） | 念网络 |

改前的两个具体问题：

1. **信号区 42×21dp**：远小于 48dp 的触控下限，老人手指压上去基本点空。
2. **点日期/农历、点"晴朗"没反应**：点击只绑在 46sp 时间大字和 34sp 温度上。

## 三、点击行为对不上（第二个真 bug）

实测日志：

```
点信号 → "念状态：电量百分之73，正在充电"      ← 一个字都没提信号
点电量 → "念状态：电量百分之73，正在充电，连着家里的无线网"
```

原来一个 `speakStatus(boolean withSignal)` 管两头，参数还用反了。
改成 `speakBattery()` / `speakNetwork()` 两个方法后实测：

```
点电量 → "念电量：电量百分之73，正在充电"
点信号 → "念网络：连着家里的无线网"
点天气 → "点天气，开始播报"
点日期 → "播报时间：现在是 16 点 59 分…"
```

## 四、两个 "FF" 不是一回事

诊断时屏幕上出现过两个 `FF`，来源完全不同，别混：

1. **运营商名**：EMUI 的 `getNetworkOperatorName()` 返回 `"FF"`（无卡/占位）。
   修法：含中文才认，否则至少 4 位字母；否则退化成「4 格」。
   > 注意 `startSignal()` 里原来有一行 `carrierName = telephony.getNetworkOperatorName();`
   > 直接赋值，绕过了过滤 —— 这个才是真正把 "FF" 写上屏幕的地方。
2. **WIFI 名**：`dumpsys wifi` 里 `SSID: "FF"`，路由器的名字就叫 FF。
   内网 WIFI 模式下显示它是**正确**的，不是乱码。

## 五、顺带发现：这台机器的上报一直是失败的

内网模式的「网络体检」里：IPv6 正常（`2408:8220:7f1e:...`），但

```
上次结果：上报失败：域名解析不了
待补发：6 条
```

用新加的「测试域名解析」当场验证：

```
解析失败（23 ms）：UnknownHostException
Unable to resolve host "shouhu.example.com": No address associated with hostname
```

同一个域名在电脑上是能解析的（只有 AAAA：`2408:8220:7f17:c0a0:...`），
说明**手机的 DNS 不返回 AAAA 记录**，中继那条路根本没通。
家人端看到的定位/电量自然是最后一次成功上报的旧数据 —— 这也是"电量不准"的第三种来源。

建议（按省事排序）：

1. 路由器/光猫的 DNS 改成 `223.5.5.5` 和 `2400:3200::1`（阿里），或 `2400:3200::1` 换成
   `2400:3200::1` 所在运营商的 IPv6 DNS；改完在手机上再点一次「测试域名解析」。
2. 如果中继有公网 IPv4，给域名加一条 A 记录，别只留 AAAA。
3. 临时应急：上报地址直接写 IPv6 字面量 `https://[2408:...]:812/api/report?k=...`
   （地址会变、证书也可能对不上，只适合排查用）。

## 七、电量条颜色分段（2.6.1）

**原来**：充电时整条固定青色 `#00897B`，不充电时 ≤15 红 / ≤35 橙 / 其余绿。
问题很直接——插着电的时候 20% 和 95% 是同一种颜色，老人看不出该不该充。

**现在**：颜色只表达"还剩多少"，充电由百分比旁边的 ⚡ 表示。

| 电量 | 颜色 | 色值 |
|---|---|---|
| 0–29% | 红 | `#E53935` |
| 30–59% | 橙 | `#FB8C00` |
| 60–100% | 绿 | `#43A047` |

几个刻意的决定：

- **三色只在 `values/colors.xml` 定义，`values-night` 不覆盖**。实心色块不是文字，
  深色模式套"变浅"那套会把 25% 变成粉红、85% 变成浅绿，反而看不出轻重
  （第一次就是这么试的，实测截图里 25% 是粉色，不像警告）。
- **低电量且未充电时，百分比数字同步变红**；充电中不标红——已经在充了，再红只会让人以为出问题。
- 阈值集中在 `BatteryBarView.LOW_PCT = 30` / `HIGH_PCT = 60`，以后要调只改这两处。

**真机实测**（`adb shell cmd battery set level N`）：

| 模拟电量 | 图标填充 | 数字 |
|---|---|---|
| 20%（拔掉充电） | 红 | 红 + 无 ⚡ |
| 25% | 红 | 白 + ⚡ |
| 30%（边界） | 橙 | 白 + ⚡ |
| 45% | 橙 | 白 + ⚡ |
| 85% | 绿 | 白 + ⚡ |

测完用 `adb shell cmd battery reset` 恢复真实电量（72% 充电中），界面立即跟上。
