# 22 · 远程恢复布局与健康检测（2.8）

> 目标：**只要网络不断，出问题能远程一键恢复**。
> 做法：老人端存一份"装好时的配置基线"，中继负责传命令，家人端点一下就行。

## 一、先去掉一个误触源：长按解锁

原来主界面「长按时间」会弹「解除屏幕固定」。问题是老人想听时间经常**按住不放**，
一按久就弹窗，等于每次听时间都可能撞上解锁。

现在长按没有任何反应。解锁只剩两条路：

1. 连点时间 8 次 → 家人设置 →「解除锁定与恢复」里的「立即解除屏幕固定」
2. 电脑端 `tools\provision.ps1 -Unlock`（手机被锁死、进不去设置时）

## 二、配置基线（手机端）

两份快照，存在 App 私有目录（含密钥，不放公共目录）：

| 快照 | 什么时候存 | 会不会被覆盖 |
|---|---|---|
| **首次基线** | 装好第一次进到桌面时自动存 | 不会。之后再改配置也不动它 |
| **手动快照** | 家人点「把当前配置存为快照」 | 会（每次覆盖上一份） |

设置页「更新与备份」里能看到两份的时间，也能手动存 / 恢复到基线。

快照内容走 `ProfileStore` 的白名单：桌面卡片、锁定开关、禁装禁卸、报时/天气、清理与通知白名单、
联系人卡片、内网模式、定位服务、DDNS、上报地址、家人号码等 30 多项。
**不含**：Device Owner 状态、系统权限（这些不是配置，恢复了也没用）。

## 三、远程命令：借上报通道下发，不做推送

老人机在内网、没有公网入口，中继连不进去，所以不做长连接/推送，改成：

```
家人端点按钮
   → POST /api/cmd?k=<令牌>  （入队）
   → 老人端下次上报（默认 10 分钟一次）
   → 中继在上报的 HTTP 响应里捎一条 {"cmd":{"id","cmd","arg"}}
   → 老人端执行
   → 下一次上报带 cmdResult 回去
   → /api/status 里能看到 cmdResult
```

好处很实际：

- 老人端不用开端口、不用保活连接
- **断网期间命令留在队列里**，网络恢复后第一次上报就取到（不会像推送那样丢了）
- 代价是延迟：最坏等于一个上报间隔（默认 10 分钟）

队列每条命令只下发一次（`Taken` 标记），执行完由结果回报删除；同一设备最多留 20 条。

### 支持的命令

| cmd | 作用 | 说明 |
|---|---|---|
| `health` | 健康检测 | 返回 `9/10 正常；缺：无障碍服务` 这样的结果 |
| `restore` | 恢复布局 | 恢复到**首次基线**；`arg=manual` 时用手动快照 |
| `save` | 存快照 | 把当前配置存成手动快照（远程备份现状） |
| `restart` | 重启桌面 | 把守护界面拉回前台（老人误退到系统桌面时用） |
| `unlock` | 解除锁定 | 关掉锁定任务开关并重启桌面，**不动 Device Owner** |

白名单之外的一律 400，避免"远程执行任意命令"的口子。

### 健康检测查什么

| 项 | 不通过意味着 |
|---|---|
| 设备所有者 | 锁定、禁装禁卸、静默授权全失效 |
| 锁定任务 | 老人可以退出桌面 |
| 无障碍服务 | 悬浮键、看门狗不可用 |
| 通知使用权 | 垃圾通知拦不住 |
| 悬浮窗权限 | 悬浮键画不出来 |
| 使用情况访问 | 统计不准（不影响主流程） |
| 电池优化白名单 | 锁屏久了定时上报会被掐 |
| 定位（权限 + 系统开关） | 查不到位置，也搜不到 WIFI |
| 主动上报 | 家人端看不到数据 |
| 网络 | 没连 WIFI 也没有移动数据 |

返回 `{"score":9,"total":10,"items":[...],"summary":"9/10 正常；缺：无障碍服务"}`。

## 四、家人端怎么用

家人端详情页多了三个按钮：

- **健康检测** → 下发 `health`
- **恢复布局** → 下发 `restore`（会二次确认，说明会覆盖当前设置）
- **存快照** → 下发 `save`

点完提示「已下发，等老人端下次上报执行（最多 10 分钟）」，
之后点「体检」就能看到「上次远程命令：health → 成功　3 分钟前　9/10 正常；缺：无障碍服务」，
以及「还有 N 条命令在中继排队」。

直连模式（老人机有公网 IPv6、家人端直连）没有这个按钮——那条路是家人端直接问老人机，
没有中间队列，提示去老人机上操作。

## 五、中继接口（自建/排障用）

```bash
# 下命令
curl -X POST "https://<中继>/api/cmd?k=<令牌>" \
     -H 'Content-Type: application/json' \
     -d '{"cmd":"health"}'
# → {"ok":true,"id":"c1a2b3c4d5","note":"已排队…"}

# 看结果（家人端也是读这个）
curl "https://<中继>/api/status?k=<令牌>"
# devices[0].cmdResult = {"id","cmd","ok","msg","at"}
# devices[0].pendingCmds = 0
```

命令队列和结果都会写进 `state.json`，中继重启不丢。

## 六、已验证 / 未验证

**已验证（Go 单测 `TestRemoteCommandFlow`）**：
下发 → 非法命令被拒 → 上报响应捎带 → 同一条不重复下发 → 结果回报 → status 可见 → 队列清空。

**未验证（需要真机 + 已部署的中继）**：
端到端时延、老人端执行 `restore` 后桌面是否立刻刷新、`unlock` 在锁定任务下能否真的退出。
你那边中继要升到 **1.6.0** 才有这个接口。
