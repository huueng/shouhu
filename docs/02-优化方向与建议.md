# 老人守护 · 优化方向与建议

> 这一份不是需求清单，是"如果这个项目要继续做三年，该怎么走"的判断。
> 有不同意见直接推翻，下面每条都标了理由和代价。

## 〇、一句话判断

现在的"老人守护"是个**合格的管控工具**，还不是一个**会被家人主动推荐的产品**。

差别在于：管控工具解决"我怕他乱点"，产品解决"我不在他身边也能安心"。
前者装完就完事，后者才有复购、口碑和延伸空间。接下来的取舍都该往后者偏。

---

## 一、产品方向

### 1. 从"管住老人"改成"少让老人操作"

老人手机上真正的痛点不是"能装乱七八糟的 App"，而是：

- 找不到东西（图标太多、桌面被自己拖乱了）
- 不敢点（怕点错、怕扣钱、怕弹窗）
- 不敢问（怕麻烦子女）

所以卡片化桌面这个方向是对的，但可以再往前走一步：**把"老人每天必做的 3 件事"做成一步到位**。

- 打电话 → 直接拨号盘，不是进通讯录（已做）
- 发微信 → 直接进"跟家人聊天"的会话，不是微信首页（可做：`Intent` 携带会话参数，或引导家人置顶）
- 看视频 → 直接进"常看的那个人"，不是推荐流

### 2. 差异化不在"锁"，在"三个安心"

| 家人的不安 | 现有方案 | 可以做的更好 |
|---|---|---|
| 他人在哪 | 短信查位置（已做） | 加"到家用 WiFi 自动报平安"——连上家里 WiFi 就发一条"妈已到家"，比 GPS 更有用，且几乎零成本 |
| 他在干什么 | 无 | 每日一条"今天用了 3 次微信、2 次抖音"的短信摘要 |
| 他会不会被骗 | 无 | 陌生号码来电播报 + 高风险关键词短信提示（"转账""安全账户"） |

**"到家报平安"是我最推荐的一个功能**：实现成本极低（监听 WiFi 连接广播 + 已存在的短信发送），但家人的感受提升最大。这类"低成本高感知"的功能应该做成一个系列。

### 3. 分层的产品线（而不是一个 App 装所有场景）

```
老人守护（手机端，本工程）  ← 单机、零服务器、主动管控
家人助守（家人端小程序/App） ← 看状态、发指令、收告警
一键部署（PC 工具）          ← 装机、批量刷机、远程排障
TVDesk（电视端）             ← 大屏陪伴、家庭信息屏
```

四件套共享同一份"老人档案"配置（JSON），这才是能规模化的结构。单机 App 永远做不大。

## 二、技术方向

### 1. 把"守护策略"变成数据，而不是代码

现在所有开关散在 `SharedPreferences` 的键里（已收口到 `Prefs`，但仍是散键）。下一步应该是一个 `Profile` 对象：

```json
{
  "name": "张阿姨",
  "tiles": ["tel", "wechat", "sms"],
  "lock": {"enabled": true, "pin": "1234"},
  "notify_whitelist": ["com.tencent.mm"],
  "locate": {"sms": true, "call_trigger": true, "family": ["138..."]},
  "chime": {"hours": [8, 12, 18]},
  "kill": {"interval": 120, "whitelist": [...]}
}
```

好处：一份 JSON 就是一台机器的全部配置 → 二维码导出、短信下发、批量刷机、云端托管全都顺了。**这是 P3 远程运维的地基，建议尽早做。**

### 2. 零服务器很好，但要知道它的天花板

短信通道的优点：不依赖任何服务、老人手机只要有信号就行。
代价：每条 0.05–0.1 元；运营商可能拦截批量短信；彩信/图片几乎不可用；无法主动推送。

建议做成**混合通道**：

- 紧急指令（定位、SOS）走短信——保证可达
- 非紧急（每日摘要、配置下发）走"有 WiFi 就联网拉、没 WiFi 就攒着"——省成本
- 家人端 App 只做"生成短信 / 读短信 / 展示"，服务器可有可无

### 3. 激活成本是这个产品的头号敌人

现状：Device Owner 只能在新机、无账号、无锁屏密码时激活，**一旦激活不可撤销**。这意味着一台手机只能装一次，试错成本极高。

可行的降低摩擦的方式，按性价比排序：

1. **PC 一键脚本**（已交付）——覆盖 80% 的"家人有电脑"场景
2. **配置前自检**：脚本先跑 `dumpsys` 判断能不能激活，不能就直说"这台机器得恢复出厂"，别让人试到一半失败
3. **出厂预置**：和老人机方案商/贴牌厂合作，出厂即集成。这是唯一能把激活成本降到 0 的方式，也是商业化的入口
4. **扫码 provisioning**：Android 的 QR provisioning 依赖 GMS，华为机型用不了，短期别指望

### 4. 别急着换技术栈

6.4k 行 Java + AndroidX，体积 2.3 MB，跑在 4 年前的荣耀 10 上没问题。**这就是优势。**
老人的机器普遍是低端机、存储紧张、系统版本停在 Android 9/10。为了"现代"换 Kotlin/Compose 会让包体涨 3–5 MB、内存涨一截，收益为负。保持 Java 8、`minSdk 23`，继续做减法。

### 5. 可观测性：出问题要能远程看到

现在崩了只能拿在手上看。加一个极轻的本地日志环（最近 200 行 + 崩溃堆栈），家人发短信"日志"就回传关键部分。**这一个功能能省掉 80% 的售后沟通。**

## 三、交付与运维

### 1. 把 provisioning 脚本做成"装机引导"而不是"命令集"

现在 `provision.ps1` 是命令行工具，家人看不懂。建议加一个双击即用的交互界面（PowerShell + WinForms/WPF 简单窗口，或直接一个本地 HTML 页面调脚本）：

```
[1/5] 已检测到：荣耀 10（Android 10）      ✓
[2/5] 安装老人守护 v2.0                    ✓
[3/5] 授予权限（8 项）                     ✓
[4/5] 开启无障碍 / 通知使用权              ✓
[5/5] 接管桌面                             ✗ 华为机型不支持，改用锁定任务 ✓
配置完成，请把手机交给家人。
```

### 2. 机型适配表是必须沉淀的资产

每装一台就记一行：机型 / 系统版本 / 默认桌面能否设 / 无障碍是否被清 / 后台是否被杀 / 特殊坑。
这件事现在看着琐碎，做到 20 台之后就是别人抄不走的东西。

### 3. 售后要有"远程陪装"

真正的家庭用户不会自己跑脚本。可以做一个"远程陪装"服务（向日葵/ToDesk 连过去，10 分钟装完），这既是收入，也是收集真实需求的最好方式。

## 四、风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| Device Owner 不可逆 | 装错只能恢复出厂，用户投诉高 | 脚本前置自检 + 装前明确告知 + 一键解锁 |
| 华为/荣耀拒绝第三方桌面 | 已实测发生，"接管"卖点打折 | 以锁定任务为主路径，桌面作为加分项；文档按机型写清楚 |
| 无障碍 + 短信 + DO 三件套 | 应用市场基本必拒，且容易被安全软件误报为木马 | 只走侧载/自有渠道；开源 + 可复现构建 + `SECURITY.md` 建立信任 |
| 定位数据 | 隐私合规红线 | 数据只在短信里点对点传，不落任何服务器——这要写进 README 当卖点 |
| 开源后被套壳加后门 | 损害品牌与信任 | 提供官方签名校验值；正式版用独立 release keystore；README 声明仅官方渠道分发 |
| 厂商系统更新 | 白名单/权限被重置 | 每次启动幂等重下发（已做）+ 自检页提示 |

## 五、和现有项目的协同（这里可能比 App 本身更有价值）

你在做的几件事其实是同一个故事的不同面：

| 项目 | 角色 | 协同点 |
|---|---|---|
| **TVDesk** | 电视端大屏 | 电视显示"妈今天几点起床、走了多少步、有没有吃药"；电视可以视频通话给手机 |
| **抖音精简版** | 老人唯一会沉迷的娱乐 | 独立 App + 一键 ADB 部署，和老人守护分开迭代，互不拖累 |
| **老人守护** | 手机端管控与守护 | 统一"老人档案"配置格式，三端共享 |
| **小智语音** | 语音入口 | "小智，给我儿子打电话""小智，我头晕"——语音是老人最低门槛的交互 |

**产品故事**：一套"给父母的数字家"——手机守规矩、电视能陪伴、语音能呼救、装机十分钟。
这个故事比"一个锁手机的 App"值钱得多，也更容易被推荐。

## 六、如果只做五件事

1. **P1 那 7 项真机回归跑完**（现在有实效但没证据，这是最大的不确定）
2. **"到家报平安"**（连上家里 WiFi 就发一条短信，成本 20 行代码，感知极强）
3. **Profile JSON + 二维码导出**（一切远程能力的地基）
4. **设置页 PIN**（防止老人自己把配置改坏，也防止小孩乱点）
5. **机型适配表 + 装机向导界面**（把一次性成功变成可复制成功）

前两件是本周就能做的，后三件是这两周的骨架。

---

## 七、一句提醒

这类项目的失败通常不是因为功能不够，而是因为**家人装不上、老人用不明白、出问题没人管**。
所以优先级永远是：装得上 > 用不坏 > 功能多。

现在"装得上"这一环，华为机型还有一道坎（默认桌面），但锁定任务这条路是通的——把这条讲清楚，比再加十个功能有用。
