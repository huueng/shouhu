# 中继在小路由器上的运行条件（MT7628 / MT7620 / MT7621 / BCM47189）

> 2026-11-12。中继已在 RAX3000M（ImmortalWrt 24.10.6 / aarch64）真机跑通；
> 下面的"最低条件"来自那份实测 + 二进制体积/数据增长测算。
> mipsel / arm 包已打好，**还没上这些真机**。

## 一句话结论

| 机器 | 代号 | 芯片 | 架构 | Flash | RAM | 官方 24.10 镜像 | 能跑中继？ |
|---|---|---|---|---|---|---|---|
| **小米路由器 mini** | R1C | MT7620A 580MHz | mipsel_24kc | 16 MB | 128 MB | 6.31 MB（`xiaomi_miwifi-mini`） | ✅ **能**（官方支持，最推荐的老机器） |
| **小米路由器 青春版** | R1CL | MT7628N 580MHz | mipsel_24kc | 16 MB | 64 MB | 5.38 MB（`xiaomi_miwifi-nano`） | ✅ **能**，必须用 UPX 版（2.0 MB） |
| **斐讯 K2** | PSG1218 | MT7620A 580MHz | mipsel_24kc | **8 MB** | 64 MB | 6.19 MB | ❌ **不行**，刷完只剩 ~1.3 MB |
| **斐讯 K2P A1/A2** | — | MT7621A 双核 880MHz | mipsel_24kc | 16 MB | 128 MB | 7.31 MB（`phicomm_k2p`） | ✅ **最舒服的 mips 选择**，剩 ~8 MB |
| **斐讯 K2P B1** | — | **博通 BCM47189** 双核 | armv7（arm_cortex-a7） | 16 MB | 128 MB | OpenWrt 官方不支持 | ✅ **包已单独出**，但得先找到能刷的第三方固件 |

一句话：**卡的不是 CPU、不是内存，是 16 MB 的 flash**。
16 MB 的机器 + UPX 版（2.0 MB）都能跑；8 MB 的 K2 直接放弃
（OpenWrt 官方对 8/64 机型本身也标了 "NOT RECOMMENDED"）。

> 机型别搞混：**R1C = mini（双频、128 MB、带 USB 2.0）**，**R1CL = 青春版（单频 2.4G、64 MB、USB 供电）**。
> 两者都是 16 MB flash，OpenWrt 都官方支持，但固件不是同一个（`miwifi-mini` vs `miwifi-nano`）。

## 中继自身的最低条件（实测 + 测算）

| 项 | 要求 | 依据 |
|---|---|---|
| 架构 | `mipsel_24kc` / `arm_cortex-a7` / `aarch64_cortex-a53` | 对应 ipk 都已出 |
| 系统 | 任意 OpenWrt 18.06+（要 opkg + procd） | init 脚本是 procd 写的，`START=95` |
| 库依赖 | **无**。静态链接（CGO_ENABLED=0），不需要 musl/openssl/libustream | RAX3000M 实测 |
| 磁盘 | 压缩版 **2.0 MB**，未压缩 5.8–6.5 MB；数据约 1 MB → **建议 overlay 剩 ≥ 4 MB** | 见下「数据增长」 |
| 内存 | 常驻 **~7 MB**（RAX3000M 实测 6.8 MB RSS），峰值 < 20 MB | 64 MB 机器够用（扣掉 LuCI 的占用） |
| 端口 | 默认 TCP 8898，可在 `config.json` 改 | — |
| 时间 | 系统时间大致正确（令牌/轨迹时间戳） | NTP 默认开即可 |
| 其他 | 不需要 TLS、不需要外网、不需要 USB | 纯 HTTP 中继 |

### 各架构二进制体积（1.15.0）

| 目标 | GOARCH | 未压缩 | UPX `--best` | ipk |
|---|---|---|---|---|
| aarch64 | arm64 | 5.75 MB | — | 2.4 MB |
| armv7 | arm (GOARM=7) | 5.81 MB | 2.00 MB（34%） | 2.0 MB |
| mipsel | mipsle (softfloat) | 6.50 MB | 1.98 MB（30%） | 2.0 MB |

UPX 的代价：每次启动解压一次，580 MHz 上大概多花 1–3 秒，启动瞬间多占约 7 MB，
起来之后和未压缩一样。`upx -t` 校验通过；Go 这边没用 `os.Executable()`，不会踩 UPX 的坑。

### 数据增长（`/etc/elderrelay/points.jsonl`）

一个轨迹点约 60 字节，10 分钟一报 → 144 点/天 → **约 8.4 KB/天**：

| 保留期 | 占用 |
|---|---|
| 30 天 | ~250 KB |
| 90 天（默认） | ~760 KB |
| 365 天 | ~3 MB |

快照只存元信息（id/时间/摘要），不存图片，可以忽略。

## 怎么自己量一台

刷好 OpenWrt 后先看这两行，再决定装不装：

```bash
df -h /overlay        # Available < 4 MB 就别折腾了
free -m               # available < 20 MB 要留意
opkg print-architecture   # 确认架构名，选对应的包
```

装完再看实占：

```bash
grep VmRSS /proc/$(pgrep elderrelay)/status
```

## 现有的包

```bash
dist/elderrelay_1.15.0_aarch64_cortex-a53.ipk              # 飞牛 / RAX3000M（已真机验证）
dist/elderrelay_1.15.0_mipsel_24kc.ipk                     # R1C / R1CL / K2P A1/A2（待真机验证）
dist/elderrelay_1.15.0_arm_cortex-a7_neon-vfpv4.ipk        # K2P B1（BCM47189，待真机验证）
dist/elderrelay_1.15.0_arm_cortex-a9_vfpv3-d16.ipk         # B1 的固件若报 a9，用这个
dist/elderrelay_1.15.0_all.ipk                             # arm64 兜底（架构名对不上时用）
```

打包：

```bash
cd elder-guardian/relay
# mips（MT7628 / MT7620 / MT7621）
GOOS=linux GOARCH=mipsle GOMIPS=softfloat CGO_ENABLED=0 \
  ../../.toolchain/go/bin/go.exe build -trimpath \
  -ldflags "-s -w -X main.Version=1.15.0" -o ../../.build/relay-mipsle .
# armv7（BCM47189 这类）
GOOS=linux GOARCH=arm GOARM=7 CGO_ENABLED=0 \
  ../../.toolchain/go/bin/go.exe build -trimpath \
  -ldflags "-s -w -X main.Version=1.15.0" -o ../../.build/relay-armv7 .

cd ../.. && python tools/build-ipk.py 1.15.0 mipsle --upx    # 出 mipsel_24kc
python tools/build-ipk.py 1.15.0 armv7 --upx                 # 出 arm_cortex-a7 / a9
```

脚本会校验 ELF 头，架构对不上直接报错（免得装上去才 exec format error）。
`--upx` 需要 `.toolchain/upx-4.2.4-win64/upx.exe`；没装就退回未压缩版，
16 MB 的机器那时候就悬了。

装的时候仍然要 `--force-signature`：

```bash
scp -O dist/elderrelay_1.15.0_mipsel_24kc.ipk root@192.168.31.1:/tmp/
ssh root@192.168.31.1 'opkg install --force-signature /tmp/elderrelay_1.15.0_mipsel_24kc.ipk'
```

## 刷机注意

### 小米 R1C（mini）
OpenWrt 官方支持，profile `xiaomi_miwifi-mini`（target `ramips/mt7620`）。
先刷 Breed（`HiWiFi HC5661A` 那套或 mini 专用 breed），再从 Breed 刷 sysupgrade。
128 MB 内存 + 双频，是这批老机器里最省心的。

### 小米 R1CL（青春版）
官方 profile `xiaomi_miwifi_nano`（target `ramips/mt76x8`）。
老固件时代有"只认 8 MB flash"的坑（wiki 记过 Designated Driver 的问题），24.10 正常。
只有 64 MB 内存，装完 LuCI 后余量不大，建议装完立刻 `free -m` 看一眼。

### 斐讯 K2
别刷了，8 MB 装完 OpenWrt 基本没空间，官方技术页明确不建议。
真想用就硬改 16 MB flash，成本比买台二手 K2P 高。

### 斐讯 K2P A1/A2
官方支持，profile `phicomm_k2p`（target `ramips/mt7621`），用 `mipsel_24kc` 包。
刷 Breed 后刷 sysupgrade。

### 斐讯 K2P B1
**芯片是博通 BCM47189（Cortex-A7 双核），和 A1/A2 的 MT7621A 完全不是一回事**，
OpenWrt 官方 24.10 没有这个型号的支持，所以：

1. 先确认机器能刷什么第三方固件（B1 常见的是 Padavan / 各家 bcm53xx 移植版，路子要自己找）；
2. 刷完在路由器上执行 `opkg print-architecture`，看它认的架构名；
3. 报 `arm_cortex-a7_neon-vfpv4` 就用 `...arm_cortex-a7_neon-vfpv4.ipk`，
   报 `arm_cortex-a9_vfpv3-d16` 就用另一个（两个包我都出了，二进制是同一个 armv7 构建）。

**别把 B1 的包刷到 A1/A2 上**，架构不同，装上去是 exec format error。
