# 微信视频通话：能做到什么、从哪开始

先给结论：**这件事能做成，而且大部分不用碰"逆向微信"**。
关键是选对通道 —— 通知（Notification）比无障碍点击稳得多，微信 8.0.79 之后尤其如此。

---

## 一、三条路，按稳定性排序

| 方案 | 依赖什么 | 稳定性 | 需要用户授权 |
|---|---|---|---|
| **A. 通知动作**（推荐） | 来电通知里的「接听 / 挂断」按钮（`Notification.Action`） | ★★★★★ 微信改界面不影响，只要还发这条通知 | 通知使用权（我们已经有） |
| **B. 无障碍文本点击** | 来电界面上「接听」这个按钮的**文字** | ★★★☆ 微信改版会挪位置，但文字很少变 | 无障碍（我们已经有） |
| **C. 坐标点击**（李跳跳那套） | 屏幕固定坐标 | ★☆ 换机型/换版本就废 | 无障碍 |

我们已经有 `ElderNotificationListener`（通知白名单）和 `ElderAccessibilityService`
（返回/主页/多任务 + 把桌面拉回前台的看门狗），三条路都接得上，不用新增权限。

---

## 二、微信版本支持矩阵

这是你最关心的"最低支持哪一版"：

| 能力 | 最低版本 | 依据 |
|---|---|---|
| **来电播报"谁邀请你视频通话"** | 7.0 起都能做 | 通知标题/正文里就带名字（`邀请你视频通话` 这类文案从 7.x 一直没变过） |
| **系统级「接听 / 挂断」动作** | **8.0.79+** | 8.0.79 才接上系统的"语音和视频通话用弹窗快捷接听"，来电变成带 Action 的通话通知，锁屏也能接 |
| **无障碍点「接听」** | 8.0.24+ 最稳 | 8.0.24 把通话界面改成"按钮更大更精简"，接听按钮文字就是「接听」；更早版本布局不同，但同样能按文字找 |
| 挂断后回桌面 | 与版本无关 | 通话结束 = 通知消失 / 界面切走，两个信号都能用 |

**建议的取舍**：把「自动接听」标成**需要微信 8.0.79 以上**，
以下版本退回"只播报 + 提醒按接听"。这样功能不会因为老人机装的是旧微信而整个失效。

> 为什么 8.0.79 是个分水岭：那之前微信通话是"应用内全屏界面"，系统根本不知道你在通话；
> 之后才把它做成系统通话通知（带接听/挂断的 Action）。前者只能靠无障碍去点，
> 后者可以直接"按"通知上的按钮 —— 这对我们意义很大：**不需要知道接听按钮在屏幕哪个位置**。

## 三、具体怎么落地（按顺序做，每步都能单独上线）

### 第 1 步：先看清真实通知长什么样（半天）

这一步不用写业务代码，但要一次真机来电：

```bash
# 老人机连着电脑，让家人用微信打一次视频电话过来，然后：
adb shell dumpsys notification --noredact > notif.txt
```

在 `notif.txt` 里找 `pkg=com.tencent.mm` 那一段，重点看三样：

1. `android.title` / `android.text`（名字和文案，决定播报怎么说）
2. `actions=[...]`（有没有「接听」「挂断」，决定能不能走 A 方案）
3. `category` / `ongoing` / `flags`（区分"来电"和"普通消息"）

> 这一步是所有后续工作的地基。没有真实 dump，只能靠猜文案，很容易做成"时灵时不灵"。

### 第 2 步：来电播报（1 天，低风险）

在 `ElderNotificationListener.onNotificationPosted` 里加一段，只做识别 + TTS 播报：

```
包名 == com.tencent.mm
  且 （title/text 含「邀请你视频通话」或「邀请你语音通话」）
  → 提炼名字 → TTS 播报「张三邀请你视频通话，按绿色按钮接听」
  → 同时震动 + 亮屏（老人可能在打盹）
```

名字怎么取：优先 `android.title`（通常是"张三"），拿不到再从正文里截
（`张三邀请你视频通话` → 去掉后缀）。**两条都失败就播"有人给你打微信电话"**，不要不播。

这条路径不依赖微信版本，7.x/8.x 都能用；风险只有一个 —— 文案变了会漏播，
所以匹配要写成"多个关键词命中任一即可"，并且做去重（同一条通知只播一次）。

### 第 3 步：自动接听（1–2 天，需要第 1 步的 dump）

按能力降级，**能用 A 就绝不用 B**：

1. **A 方案**：通知里有 `接听` 这个 Action → 直接 `action.actionIntent.send()`。
   等价于用户点了通知上的接听，微信界面怎么改都不影响。
2. **B 方案**：没有 Action（老版本）→ 用无障碍找文字包含「接听」的可点击节点，`performAction(CLICK)`。
   找到了就点，找不到就**放弃并播报"请按绿色按钮"**，绝不瞎点坐标。
3. 不建议上 C 方案。同一台机器换个字体/分辨率就可能点到"挂断"上。

开关放在设置里（默认**关**），因为"自动接听"在伦理上要家人明确同意。

### 第 4 步：挂断后自动回主界面（半天）

两个信号，任一命中就回桌面：

- 那条通话通知被移除（`onNotificationRemoved`）
- 无障碍发现前台从 `com.tencent.mm` 变成别的

回桌面直接用现有的 `ElderAccessibilityService`：
`performGlobalAction(GLOBAL_ACTION_HOME)` —— 我们本身就是桌面，等于回到老人熟悉的那一屏。
不需要新的权限，也不用 `startActivity` 抢焦点。

注意加 2 秒防抖：微信挂断时会有"通话结束"页，过早跳回会显得很突兀。

### 第 5 步：主界面「微信电话」（这块最难，建议最后做）

微信**没有**公开的"呼叫某人"deeplink（`weixin://` 只对聊天/扫一扫之类有效，
而且不同版本行为不一致）。所以只有三种做法：

| 做法 | 体验 | 代价 |
|---|---|---|
| 只放一张「微信」卡片 | 打开微信，老人自己点 | 零风险，但不解决"不会打" |
| 卡片 + 大字提示 + 语音引导 | 打开微信并播报"请点开要打给的人" | 低风险，能救一部分场景 |
| 无障碍脚本走完整流程（搜索→进聊天→点＋→视频通话） | 一键拨出 | 高成本：微信每次改版都可能失效，要按版本维护步骤 |

**建议先做第二种**。真要做第三种，也不要写死坐标，按"文字 + 层级"走，
并把步骤做成配置（JSON），失效时改配置而不是发版。

## 四、我们会踩的坑（先记下来）

- **文案/结构会变**：所以第 1 步的 dump 要留档，后面每次微信大版本更新都复核一次。
- **通知去重**：同一次来电微信会连发几条通知（响铃、悬浮、通话中），必须按
  `key + 文案` 去重，否则老人会听到连播三遍。
- **勿扰/静音**：老人机常被调成静音，TTS 要显式走媒体流并把音量顶上去
  （我们已经有远程调音量，可以配合）。
- **无障碍被系统杀掉**：华为/荣耀常见，现有看门狗只保证"桌面回来"，
  通话相关的动作要能容忍服务短暂不可用（失败就退回播报）。
- **合规**：只读通知里"谁在呼叫我"这一条，不读聊天内容、不落库；
  家人端能看到"今天接过几次微信电话"就够了，通话内容一概不碰。

---

## 五、一句话总结

先做**第 1、2 步**（抓一次真实通知 + 播报名字），这两步没有风险、不依赖版本；
确认通知里有没有「接听」动作之后，再决定第 3 步走 A 还是 B。
微信 8.0.79 以上可以直接按通知按钮，8.0.24–8.0.78 用无障碍点文字，
更低版本只播报不自动接 —— 功能逐级降级，不会整块失效。
