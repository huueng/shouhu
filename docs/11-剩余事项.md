## 一、上线前必做（不做会有真实风险）

| # | 事项 | 为什么必须做 | 大致工作量 |
|---|---|---|---|
| 1 | **正式签名替换 debug 签名** | 现在用的是 `~/.android/debug.keystore`。debug 证书默认密码公开，任何人可以签一个同包名的包覆盖安装（只要不是从商店装）。给家人用的正式版必须换 | 半天（含重新装机流程） |

| 3 | **开机自启 + 锁定任务**再回归一次 | 已验证过一次，但换签名重装后要重验（新装的 App 会被系统冻结到首次启动） | 10 分钟 |
| 4 | **记录「首次发短信要 4 位验证码」** | 家人第一次用会懵；写进部署说明（已写进 docs/04，需要同步到 README 部署段） | 10 分钟 |

| 5 | **Profile JSON**（一份 JSON = 一台老人的全部配置） | ★★★★ | 二维码导出、批量刷机、换机迁移全靠它。也是"少发版"的基础 |
| 6 | **`/status` 扩展字段**（步数、最后亮屏时间、陌生来电数） | ★★★ | 成本低，家人感知强。见 `docs/07` |
| 7 | **自动更新**（检查新版本 → 提示家人） | ★★★ | 现在只能靠电脑推。可做"连 WiFi 时检查一个静态 JSON，有新版就提示" |
| 8 | **电脑端支持"扫码配网"**（把位置二维码读进来，一键填好） | ★★☆ | 现在要手输域名；加个截图粘贴/拖拽识别二维码会舒服很多 |

| 实时屏幕画面 / 通讯录上传 | 隐私红线 |

## 附：主动上报到底要不要服务器？

**不需要"我们的"服务器，但需要一个"接收方"。** 数据从哪儿来、往哪儿去，可以拆成三件事看：

| 环节 | 现状 | 说明 |
|---|---|---|
| 数据存在哪 | **老人机本地**（`files/track.jsonl`、`usage.json`） | 不依赖任何服务器，断网照样记 |
| 怎么"主动"发出去 | `ReportUploader` 每小时 POST 一次 | 需要一个能收 JSON 的地址，填了才发 |
| 谁能收 | ① 家里 NAS / 软路由（推荐）② 家人端（若做服务端）③ 任意 webhook（ntfy / Server 酱 / 云函数） | 都不需要公网 IP 的只有 ①，但只在连家里 WiFi 时能收到 |

**所以现在的形态是**：
- 不配地址 → 完全离线，家人靠「查询 + 拉轨迹」拿数据（现状）
- 配了 NAS → 老人在家时自动补传，回家就有完整轨迹
- 配了公网 webhook → 在外面也能上报（要能出网，老人机本来就常连 WiFi）

真要做到"**越界立刻报警**"，还缺一环：家人端得有常驻接收方 + 推送。
这一步建议等有 NAS 或愿意让家人端常驻后台时再做。
