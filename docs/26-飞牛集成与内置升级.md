# 26 · 飞牛集成：应用设置项、桌面快捷方式、内置升级

对应你发的那张「应用设置」截图（easydown 的 桌面访问 / 访问端口 / 访问路径 / 自定义 URL），
以及「每次改中继都要传 fpk」这件事。

---

## 一、截图里那几项，分别由什么决定

| 截图里的字段 | 来自哪里 | 我们现在的值 |
|---|---|---|
| 应用账号 | fnOS 安装时按 `appname` 生成的系统用户 | `elderrelay`（自动） |
| 安装位置 | fnOS 的选择（系统分区 / 存储空间），fpk 只能给默认 | 由安装时选 |
| **桌面访问**（仅管理员 / 设备内所有用户） | `app/ui/config` 里 `.url` 的 **`allUsers`** | `true` = 设备内所有用户 |
| **访问端口** | `manifest` 的 **`service_port`** ＋ `app/ui/config` 里 `.url` 的 `port` | 刚补上 `service_port=8898`（之前只有 config，所以设置页不显示端口） |
| **访问路径** | `app/ui/config` 里 `.url` 的 **`url`** | `/`（管理台） |
| **自定义 URL** | fnOS 自己提供的（DDNS/域名转发），fpk 不控制 | 你可以在应用设置里自己填 |

之前「访问端口」是空的，就是因为 manifest 少了 `service_port` —— 这次补上了：

```ini
appname=elderrelay
version=1.8.0
service_port=8898      # ← 新增，应用设置里才会显示端口
desktop_uidir=ui
desktop_applaunchname=elderrelay.Application
```

`app/ui/config` 里 `port` 必须和 `service_port` 一致，且是**字符串**：

```json
"elderrelay.Application": {
  "type": "url",          // url=新标签页打开；iframe=飞牛桌面窗口内嵌
  "protocol": "http",
  "port": "8898",
  "url": "/",
  "allUsers": true        // false 就是截图里的「仅管理员」
}
```

## 二、桌面快捷方式

要出现图标，**三样缺一不可**：

1. `app/ui/images/icon_64.png` 和 `icon_256.png`（`{0}` 占位符会被替换成这两个尺寸）
2. `app/ui/config` 里的一条 `.url` 条目，且 **key 必须以 appname 开头**
   （`elderrelay.xxx`，否则桌面不认）
3. `manifest` 里 `desktop_uidir=ui` + `desktop_applaunchname=<某个 .url 的 key>`

这次多给了一个入口 —— **「家人视角」**，指向 `/f`：

```json
"elderrelay.Family": { "title": "家人视角", "icon": "images/icon_{0}.png",
                       "type": "url", "protocol": "http", "port": "8898",
                       "url": "/f", "allUsers": true }
```

于是飞牛桌面上会有两个图标：

- **守护中继** → `/`（管理台：设备、令牌、围栏、密码、升级）
- **家人视角** → `/f`（家人页：位置、地图、轨迹、围栏、催一次定位）

`/f` 不带参数时会先出一个**老人选择页**（点谁进谁），这样加老人不用改图标。

> 装完/覆盖安装后桌面图标没刷新？在飞牛上执行一次：
> `systemctl restart trim_app_center.service`

## 三、内置升级（不用再传 fpk）

### 3.1 原理

中继自己去「更新源」拿一个 JSON，比较版本 → 下载对应架构的二进制 → 校验 sha256 →
替换到 `<应用数据目录>/current/elderrelay` → **原地重启**（Linux `syscall.Exec`，PID 不变，
服务管理器不会以为应用挂了）。

为什么不直接覆盖 fpk 装出来的目录：那里通常是只读的、而且下次重装 fpk 会被覆盖掉。
所以升级装到数据目录，启动脚本优先用它：

```
cmd/main: 先找 <var>/current/elderrelay → 再找 <target>/elderrelay
cmd/upgrade_callback: 重装 fpk 时把 current/ 改名藏起来 → 让新包生效
```

### 3.2 更新源长什么样

```json
{
  "version": "1.8.1",
  "notes": "修了 xxx",
  "files": {
    "linux-amd64": {"url": "https://…/elderrelay-linux-amd64", "sha256": "…"},
    "linux-arm64": {"url": "https://…/elderrelay-linux-arm64", "sha256": "…"},
    "linux-arm":   {"url": "https://…/elderrelay-linux-armv7",  "sha256": "…"}
  }
}
```

`files` 的键是 `GOOS-GOARCH`（`linux-amd64` / `linux-arm64` / `linux-arm`），
中继会按自己运行的架构取对应那个。

### 3.3 发布一个新版本（一条命令）

```bash
bash tools/publish-update.sh 1.8.1 https://你的静态站/relay
```

它会：
- 交叉编译 `linux-amd64` / `linux-arm64` / `linux-armv7`（`-trimpath -s -w`，各约 6MB）
- 算好 sha256，生成 `dist/update/update.json`
- 打印下一步要做的事

把 `dist/update/` 整个传到那个地址（GitHub Release、自己域名、CF 后面的静态站都行），
然后在中继的 `config.json` 加一行：

```json
"update_url": "https://你的静态站/relay/update.json"
```

重启中继，管理台版本卡片就会多出「检查更新」按钮。

### 3.4 升级流程（在网页上点两下）

1. 管理台 → 版本 → **检查更新**
2. 有新版会显示「发现新版本 1.8.1」+ 更新说明 + **立即升级**
3. 点升级：下载（约 8MB）→ 校验 → 替换 → 原地重启，页面会自动等到新版本号出现

整个过程老人端/家人端最多断几秒（长轮询会自己重连），位置数据不会丢。

### 3.5 回滚

两种情况：

- **想退回 fpk 里的版本**：重装一次同版本（或更新版本）的 fpk 即可 ——
  `upgrade_callback` 会把 `current/elderrelay` 改名成 `.replaced-时间戳`，包内版本重新生效。
- **只想临时跑旧二进制**：把 `<var>/current/elderrelay.replaced-xxx` 改回 `current/elderrelay`，
  再重启应用。

### 3.6 注意

- 中继要能**出网**（下载更新包）；它本来就要访问外网吗？不一定 ——
  如果 NAS 完全不出网，这个功能用不了，只能继续传 fpk。
- 更新源建议放 HTTPS；sha256 是硬校验，下载坏了/被替换都会拒绝（实测：给错 sha 时
  `校验不通过：期望 000…，实际 06ff…`，且**一个字节都不会替换**）。
- 原地重启靠 Linux 的 `syscall.Exec`：Windows/macOS 上跑只做下载校验、不会重启（本机调试用）。

## 四、这次改动的文件清单

| 文件 | 改了什么 |
|---|---|
| `relay/fpk/manifest` | 加 `service_port=8898`，版本 1.8.0 |
| `relay/fpk/app/ui/config` | 加「家人视角」入口（`/f`） |
| `relay/fpk/cmd/main` | 启动时优先用 `<var>/current/elderrelay` |
| `relay/fpk/cmd/upgrade_callback` | 重装 fpk 时把 current/ 改名，让新包生效 |
| `relay/update.go` | 检查/下载/校验/替换 + 两个接口 |
| `relay/update_exec_linux.go` | `syscall.Exec` 原地重启 |
| `relay/update_exec_other.go` | 非 Linux 的降级实现（保证本机能编译调试） |
| `relay/family_home.go` | `/f` 无参数时的老人选择页 |
| `relay/main.go` | 版本卡 + 更新按钮、`/f` 分流、路由 |
| `relay/store.go` | `Config.UpdateURL` |
| `tools/publish-update.sh` | 一条命令出三架构 + update.json |
| `tools/build-fpk.sh` | 版本号改为构建注入（`-X main.Version`） |

> 顺带修掉一个隐患：以前版本号是源码里的 `const`，改包不改常量就会出现
> 「升了 1.6.2 却显示 1.6.1」。现在打包和发布脚本都用 `-ldflags -X` 注入，
> **manifest 里写多少，程序就报多少**。

## 五、1.9.0：为什么「上传了新包，设置还是老样子」

你截图里那块空白，不是 `service_port` 的问题，是**包结构多套了一层目录**。

对比官方 `fnpack` 打出来的 `app.tgz`：

```
# 官方（对的）
elderrelay
ui/config
ui/images/icon_64.png
config/privilege
config/resource

# 我们之前（错的）
app/elderrelay
app/ui/config
app/ui/images/icon_64.png
```

我们打包时写的是 `tar -czf app.tgz app`（把 `app` 这个**目录**打进去），
解到 `target/` 之后就变成 `<target>/app/ui/config`；
而飞牛读的是 `<target>/ui/config` —— 读不到，于是：

- 桌面入口/图标信息拿不到
- 「应用设置 → 常规 → 访问端口/访问路径/桌面访问」整块不显示
- 程序还能跑，只是因为 `cmd/main` 里我写了兜底路径 `<target>/app/elderrelay`

修法：改成把 `app/` 里的**内容**打进根（`cd app && tar ... elderrelay ui config`），
并把 `config/` 也放进 `app.tgz`（官方就是这么打的）。现在结构和官方逐字节一致：

```
elderrelay
ui/config
ui/images/icon_64.png
ui/images/icon_256.png
config/privilege
config/resource
```

> 验证方式：`tar -xzOf dist/elderrelay-1.9.0.fpk app.tgz | tar -tzf -`
> 顺便说一句，官方的 `fnpack build` 我也跑通了一次（`fnpack-1.2.3-windows-amd64`），
> 就是拿它的产物对照才定位到这层多余目录的。

装 1.9.0 之后，应用设置里应该出现「访问端口 8898 / 访问路径 / / 桌面访问」。
如果桌面还没刷新：`systemctl restart trim_app_center.service`。

## 六、1.9.0 的其他改动（按你的要求）

### 6.1 一个入口、两个标签

- 桌面**只留一个图标**「守护中继」，点开是 **家人页**（默认）
- 页面顶部两个标签：**家人页 | 中继页**，中继页就是原来的管理台（`/admin`）
- `/f?k=令牌` 这种单设备分享链接仍然保留，不受影响

为什么不用一个 HTML 全并进去：家人页和手机 App 共用同一份 `index.html`
（构建时复制过去），合并代码只会让两边都难维护；用同一个路由切两个视图，
既是一个入口，也不用养两套页面。

### 6.2 家人页在网页里的精简

网页版用不到的几块都去掉了（注入 CSS/JS 隐藏，不改共用文件）：

| 去掉的 | 原因 |
|---|---|
| 添加老人（相机扫码 / 相册选图 / 手动填写） | 中继里已经绑定了，浏览器没摄像头也没必要扫码 |
| 自动刷新（每 3 分钟） | 网页是打开看一次，不需要后台轮询 |
| 后台提醒 | 那是手机 App 的常驻服务，网页里没有意义 |

改成：页面直接从 `/api/*` 读**中继里已绑定的全部老人**写进本地存储，
列表里就是它们；只有一位时自动进入详情。

### 6.3 在线更新 → 手动上传

在线更新先撤了（你说暂时用不到），换成中继页的「版本」卡：

```
[选择文件]  [上传并升级]
```

- 上传的是 `dist/update/elderrelay-linux-amd64` 这类**二进制**（`publish-update.sh` 生成）
- 校验两条：文件 ≥1MB，且以 ELF 开头（传成 apk/txt 会被当面拒绝）
- 通过后替换到 `<var>/current/elderrelay` 并原地重启
- 想回退：重装一次 fpk 即可

接口还在（`/api/update/check`、`/api/update/apply`），没删 —— 等以后要在线更新时
配上 `update_url` 就能用，不用改代码。
