## 一、这次交付了什么

| 文件 | 说明 |
|---|---|
| `dist/elderrelay-1.0.0.fpk` | 飞牛离线安装包，**不依赖 Docker、不联网拉镜像** |
| `elder-guardian/relay/` | 中继服务源码（Go，纯标准库，零第三方依赖） |
| `elder-guardian/relay/relay_test.go` | 8 个测试，覆盖判定、状态机、HTTP 全链路 |
| `tools/build-fpk.sh` | 一条命令重新打包 |
| `tools/gen-icon.py` | 盾牌图标生成（纯 Python，不依赖 Pillow） |

**为什么是 native 版而不是 Docker 版**：飞牛的 Docker 版 fpk 只打包 compose 文件，安装时还要去拉镜像。你要离线装，所以走 native——Go 静态二进制直接跑，整个包里没有任何外部依赖。

> ⚠️ **别拿错包**：`.fpk` 里装的是 **linux/amd64** 二进制，只适用于 **x86_64 的飞牛主机**（比如 WYSE 5070 这类小主机、普通 PC）。
> - ARM 飞牛主机：下载 Release 里的裸二进制 `relay-arm64`，自己配个 systemd 服务就行。
> - Release 里的 `*_aarch64_cortex-a53.ipk` 是给 **aarch64 路由器**（RAX3000M 等）的 OpenWrt 包，
>   **不是飞牛的**，飞牛装不了 ipk。

## 二、安装（三步）

1. 把 `elderrelay-1.0.0.fpk` 拷到 NAS 任意目录
2. 飞牛桌面 → **应用中心 → 右上角设置 → 手动安装应用** → 选这个文件
3. 装完后桌面出现「守护中继」图标，点开就是状态页

如果安装报错，把应用中心里那一行报错原文留下来，`cmd/main` 的日志在数据目录的 `app.log`。

## 三、找两个令牌

首次启动会自动生成配置，状态页上会直接显示**数据目录**，一般是：

```
/vol1/@appdata/elderrelay/config.json
```

打开它，里面有两个东西：

| 字段 | 给谁用 |
|---|---|
| `family_token` | 家人端 App，用来读状态和拉事件 |
| `devices[].token` | **老人端**，用来上报 |

```json
{
  "port": 8898,
  "family_token": "62032c15355ba352",
  "devices": [{ "id": "elder1", "name": "老人", "token": "29fc159d022cb4d1" }],
  "offline_minutes": 90,
  "keep_days": 90
}
```

`name` 可以改成"爷爷""外婆"，会出现在告警文案里。改完重启应用生效。

## 五、设围栏

家人端 App 还没改，先用 curl。**支持多个围栏**，家一个、乡镇街一个，各自独立判定。

```bash
BASE="http://[IPv6]:8898"
K="你的family_token"

# 家：500 米
curl -X POST "$BASE/api/fence?k=$K" -H "Content-Type: application/json" -d '{
  "name":"家","lat":39.9006,"lon":116.3944,"radius":500,"enabled":true
}'

# 乡镇街：800 米
curl -X POST "$BASE/api/fence?k=$K" -H "Content-Type: application/json" -d '{
  "name":"乡镇街","lat":39.95,"lon":116.45,"radius":800,"enabled":true
}'

# 看当前围栏
curl "$BASE/api/fence?k=$K"
```

**建议**：设围栏的时候让老人待在家里/街上，取当前点当圆心。如果人在外面设，圆心就错了。

### 多边形（方框）已经预留

中继的判定已经支持任意多边形，只是家人端还没有画图界面：

```bash
curl -X POST "$BASE/api/fence?k=$K" -H "Content-Type: application/json" -d '{
  "name":"菜市场","shape":"polygon","enabled":true,
  "points":[[39.9,116.394],[39.9,116.396],[39.902,116.396],[39.902,116.394]]
}'
```

`points` 是 `[纬度, 经度]` 的有序顶点，顺逆时针都行。将来家人端做"画方框"时，前端把四个角传上来即可，**中继不用改**。

## 六、对接老人端

在老人端 **设置 → 远程与联网 → 上报地址** 填：

```
http://xxx.dynv6.net:8898/api/report?k=设备token
```

### 现在的兼容性

中继**同时兼容两种报文**，所以老人端第一版可以不做任何代码改动：

- 老人端现有的 `{"device","version","time","status":{...},"track":[...]}`
- 中继的简化格式 `{"pos":{"t","lat","lon","acc"},"battery":76}`

### 但有一个必须改的地方

**现在老人端是每小时上报一次**（`ReportUploader` 里写死的 60 分钟）。这个频率下，围栏告警最差要 75 分钟才能到——太慢了。

需要改三处（下一步）：

| # | 改动 | 原因 |
|---|---|---|
| 1 | 上报间隔改可配，默认 **10 分钟** | 决定告警延迟 |
| 2 | **每次采样都上报当前位置**，不只在"移动 ≥80 米"时 | `TrackReceiver` 现在是"动了才记点"，围栏判定需要"每次都报" |
| 3 | 越界后临时提速到 1 分钟 | 可选，让告警更快 |

## 七、接口一览

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/` | 无 | 设备索引（可加/删老人） |
| GET | `/d/<id>?k=` | 该设备令牌 | 单老人页（二维码、上报地址、围栏） |
| GET | `/api/health` | 无 | 健康检查 |
| POST | `/api/report?k=` | 设备令牌 | 老人端上报 |
| GET | `/api/events?since=&wait=55&k=` | 设备令牌 | **长轮询**，有事件立即返回，无事件 55 秒后 204 |
| GET | `/api/status?k=` | 设备令牌 | 该老人快照（含围栏内外） |
| GET | `/api/track?since=&limit=&k=` | 设备令牌 | 轨迹点 |
| GET/POST/DELETE | `/api/fence?k=` | 设备令牌 | 围栏增删改查（只操作自己名下的） |
| GET | `/api/qr?t=family\|elder&k=` | 设备令牌 | 二维码 PNG |
| POST | `/api/token?k=` | 设备令牌 | 重置该设备令牌 |
| POST/DELETE | `/api/device` | 无 | 新增 / 删除老人（与首页同级） |
| GET | `/api/config?k=` | 设备令牌 | 运行参数 |

### 事件字段

```json
{
  "id": 7, "t": 1761450000000,
  "device": "elder1", "deviceName": "爷爷",
  "kind": "fence_out",
  "fenceId": "f1", "fenceName": "家",
  "lat": 39.9096, "lon": 116.3944,
  "dist": 1002, "acc": 20,
  "text": "离开了「家」"
}
```

`kind` 四种：`fence_out`（离开）、`fence_in`（回来）、`offline`（失联）、`online`（恢复上报）。

### 长轮询怎么用（家人端要按这个接）

```
GET /api/events?since=<上次的cursor>&wait=90&k=<token>
→ 200 + {"cursor":8,"events":[...]}   有事件
→ 204                                 90 秒内没事件，客户端立刻重连
```

`cursor` 单调递增，客户端存本地，重连不会漏也不会重复。

## 九、端口与防火墙

| 项 | 值 |
|---|---|
| 端口 | **8898**（刻意避开老人机 `LocateServer` 的 8899） |
| 协议 | TCP |
| 监听 | Go 的 `:8898` 默认双栈，有 IPv6 就同时听 v4/v6 |

飞牛如果开了防火墙，要放行入站 TCP 8898。路由器侧如果对 IPv6 做了入站限制，也要放行。

**离线安装不需要 Docker**，所以飞牛的 Docker 服务没启动也不影响。

### 9.1 走 Lucky / Nginx 反代（推荐）

如果已经有 Lucky 做泛域名 + HTTPS，可以让中继**只监听本机**，不暴露到公网：

```json
"bind": "127.0.0.1:8898"
```

然后 Lucky 加规则：`shouhu.example.com` → `http://127.0.0.1:8898`。

**四条必须注意**：

| # | 要点 | 原因 |
|---|---|---|
| 1 | **上游超时保持默认即可** | 服务端已把长轮询上限压到 **55 秒**（低于 nginx/Lucky 默认的 60 秒），所以默认配置下不会撞超时。如果你把 Lucky 超时调小了（比如 30 秒），那才需要调回来 |
| 2 | **路径原样透传** | `/api/report`、`/api/events` 不能在反代里重写或加前缀 |
| 3 | **证书要能被 Android 验证** | Let's Encrypt 正式证书可以（荣耀 10 是 Android 10，信任 ISRG Root X1）；**自签证书老人端会报 `SSLHandshakeException`** |
| 4 | **反代不解决 IPv4 可达性** | 域名只解析到 AAAA 时，在 IPv4-only 网络（公司 WiFi、商场）照样连不上。反代只是换了个名字，网络层没变 |

**关于端口**：

812 这类非标准端口，只要 DNS 直接解析到 NAS（不经 Cloudflare 代理），完全可用，URL 里带上端口就行：

```
https://shouhu.example.com:812/api/report?k=<设备令牌>
```

唯一要注意的是：**Cloudflare 免费版只代理固定端口**（80 / 443 / 8080 / 8443 / 2053 / 2083 等），812 不在列表里。所以哪天想让 CF 帮忙遮住源站或补 IPv4 入口，得换成 443 或 8443。不用 CF 就没有这个限制。

### 9.2 长轮询与反代超时的关系

```
家人端 GET /api/events?since=7&wait=90
   ↓ 服务端夹到 55 秒
   ├─ 有事件 → 立即 200 返回
   └─ 无事件 → 挂住 55 秒 → 204
                ↑
                └─ 低于 nginx/Lucky 默认的 60 秒，所以不会被反代先掐断
```

**为什么上限是 55 而不是更长**：nginx 系反代的 `proxy_read_timeout` 默认 60 秒。如果把长轮询挂到 90 秒，每一轮都会在 60 秒处被反代断开（504），日志刷满错误、每次重连还有 1–2 秒空窗。

把它压在 55 秒，代价是请求频率略高（约 1570 次/天，流量 1 MB 量级），换来的是**反代零配置也能稳定工作**。客户端传任何大于 55 的 `wait` 都会被夹到 55。

如果你在 Lucky 里把超时调大了（比如 180 秒），可以把 `wait` 也调大省点电——但没必要，收益很小。

### 9.3 家人端常驻（2.1 起）

家人端装完默认就常驻：通知栏会有一个「守护」小图标，关掉 App 也会继续收告警。

**它做两件事**：

| 模式 | 怎么工作 | 围栏在哪算 |
|---|---|---|
| **中继** | 每 60 秒拉一次 `/api/events`，有事件就弹通知 | 服务端算 |
| **直连** | 每 60 秒问 `/status`；每 5 分钟问 `/loc` | **本地算**（同样的精度缓冲 + 连续两点确认） |

直连模式的本地判定规则和中继一致：`d - acc > r` 才算确定在外，`d + acc < r` 才算确定在内，模糊带维持原状态；连续两次在外才报。

**会提醒的几件事**：离开围栏、回到围栏、手机关联（超时没上报）、低电（≤20% 且没充电）、被调成静音。

**不想常驻**：App 首页有「关闭后台提醒」按钮，关掉后通知栏图标消失，只剩手动查看。

**国产 ROM 需要手动放行**（不做的话可能一天就被系统杀掉）：

| 品牌 | 设置路径 |
|---|---|
| 华为 / 荣耀 | 设置 → 应用启动管理 → 找到「守护同步端」→ 改为手动管理，三个开关全开 |
| 小米 | 设置 → 应用设置 → 应用管理 → 守护同步端 → 省电策略「无限制」+ 自启动 |
| OPPO / vivo | 设置 → 电池 → 应用耗电管理 → 允许后台运行 + 自启动 |
| 三星 | 设置 → 电池 → 后台使用限制 → 从「休眠应用」里移除 |

再加一步通用操作：最近任务里下拉/长按把 App **加锁**，避免一键清理。

**怎么确认它真的在跑**：下拉通知栏，看到「守护 · 正在守护 N 位老人」就是在跑。如果显示「还没有配置老人」，说明网页那边没同步过来（打开一次 App 即可）。

## 十、排错

| 现象 | 原因 | 处理 |
|---|---|---|
| **装不上，提示「应用包不符合系统要求」** | 这是 manifest 校验没过。常见四种：缺 `platform`、缺 `os_min_version`、`config/resource` 带换行、`cmd/` 下生命周期脚本不全（要 9 个） | 用 `tools/build-fpk.sh` 重新打包，脚本已经全部处理好并自检 |
| 装完点图标白屏 | 服务没起来 | 看数据目录 `app.log` |
| 日志说"找不到程序文件" | `app.tgz` 展平方式与该版本不符 | `cmd/main` 已做双路径探测（`target/` 与 `target/app/`），仍报错说明包里确实没二进制 |
| 手机打不开状态页 | IPv6 不通 / 防火墙 | 先在家用局域网地址试，再出门试 |
| 状态页显示"离线" | 老人端没上报到 | 检查上报地址里的令牌和端口 |
| 一直不报警 | 上报频率太低 / 围栏圆心错了 | 看 `/api/status` 里的 `fences[].inside` |
| 疯狂误报 | 定位精度太差 | 把半径调大，或看 `acc` 是否常年 >500 |
| 告警只在偶数次出现 | 这是设计 | 连续两点确认，防止单点漂移 |
| 反代后每小时刷 504 | 长轮询超过反代超时 | 见 9.1 第 1 条 |
| 老人端报 SSLHandshakeException | 反代用了自签证书 | 换 Let's Encrypt 正式证书 |

**判断误报的快捷方法**：`/api/status` 里看 `acc` 字段。如果 `acc` 常年 500 以上，说明这台机器基本只能拿到网络定位，围栏半径至少设到 800–1000 米才有意义。

## 十二、重新打包


改完代码后：

```bash
bash tools/build-fpk.sh 1.0.1
```

会自动编译 linux/amd64、生成图标、拼装、打 fpk。产物在 `dist/`。

**注意**：Windows 上打包容易丢可执行位，脚本里已经用 `tar --mode=755` 处理了。打包完脚本会打印权限检查结果，确认 `app/elderrelay` 是 `rwxr-xr-x`。
