# 兼容性评估与配置向导设计

## 一、最低能适配到安卓几

先说结论：**装得上最低 Android 6.0（API 23），用得顺建议 Android 8.0（API 26）以上**。

理由不是"能不能跑"，而是几个关键能力的最低 API：

| 能力 | 用到的 API | 最低版本 |
|---|---|---|
| Device Owner 静默授予权限 | `setPermissionGrantState` | **6.0 / API 23** |
| 锁定任务（禁 HOME/后台键） | `setLockTaskPackages` `startLockTask` | 5.0 / API 21 |
| 禁止安装 / 禁止卸载 | `DevicePolicyManager` | 5.0 / API 21 |
| 防卸载自身 | `setUninstallBlocked` | 5.0 / API 21 |
| 通知白名单 | `NotificationListenerService` | 4.3 / API 18 |
| 悬浮键 / 看门狗 | `AccessibilityService` | 4.0 / API 14 |
| 前台服务（定位/DDNS/传包） | `startForeground` | 4.0 / API 14 |
| 通知渠道 | `NotificationChannel` | 8.0 / API 26 |
| 网络切换监听 | `registerDefaultNetworkCallback` | 5.0 / API 21 |
| 使用统计（体检里的常用应用） | `UsageStatsManager` | 5.0 / API 21 |
| 公共 Download 目录直写 | `requestLegacyExternalStorage` | 仅 Android 10 生效 |
| 按应用禁用移动数据 | `setMeteredDataDisabledPackages` | **11 / API 30** |

也就是说：
- **Android 5.x 装不上**（minSdk 23），也不建议硬下探——5.x 没有 `setPermissionGrantState`，
  权限得让家人在设置里一个个点，装机体验直接崩。**保持 minSdk 23 是对的。**
- **Android 6–7**：能跑，但通知没有渠道、后台限制逻辑较老，部分国产 ROM 的前台服务容易被杀。
- **Android 8–11**：推荐区间，也是绝大多数老人机的实际系统版本。
- **Android 11+**：多一个"按应用禁用移动数据"的能力（见下一节）。

> 本机实测：荣耀 10 / Android 10 / EMUI 10，全部功能正常。

## 二、应用联网限制：能不能做

**结论：部分能做，而且只有 Android 11 以上能做；Android 10 及以下没有公开 API。**

| 方案 | 能否限制联网 | 前提 | 说明 |
|---|---|---|---|
| `DevicePolicyManager.setMeteredDataDisabledPackages` | ✅ **只限移动数据** | 设备所有者 + **Android 11+** | 官方接口，按包名禁止用流量；WiFi 仍可上网 |
| `NetworkPolicyManager.setUidPolicy` | ✅ 全部网络 | `MANAGE_NETWORK_POLICY`（系统签名） | 普通应用拿不到 |
| iptables / nftables | ✅ 全部网络 | **root** | 最彻底，但要刷机 |
| 关闭移动数据总开关 | ✅ 全局 | 用户手动 | 一刀切，老人自己也会被断网 |
| 后台清理 + 通知白名单 | ❌ 不省流量 | 无 | 只能减少后台活动，不能阻止联网 |

**所以我的建议是：**

1. **不在首次配置里推荐这一项**——大多数老人机还在 Android 9/10，开了也不生效，反而让人以为设好了。
2. 在设置里做一个「限制移动数据（仅 Android 11+）」开关：
   - Android 11+ 且已激活 DO → 真正调用 `setMeteredDataDisabledPackages`，白名单里的应用允许用流量，其余禁止；
   - 低版本 → 直接显示"当前系统不支持（需要 Android 11 及以上）"，并给出替代建议（关移动数据 / 用 WiFi 限制路由器）。
3. 默认白名单沿用「通知白名单 + 清理白名单」那批应用（微信、QQ、短信、电话、支付宝…），家人不用重新选一遍。

**真正省流量的更有效组合**其实是：通知白名单（少弹窗少刷新）+ 周期清理后台 + 关掉自启，联网限制是锦上添花。

## 三、首次配置：我的方案

你提的两个方向（"进设置配好再进主界面" vs "首屏就是设置"）其实是同一个东西。我建议做成 **4 步向导，每步都能跳过**：

```
① 欢迎         3 句话说明这是干什么的 + 「开始配置」/「直接进入」
② 桌面放什么   预勾选：打电话、发短信、微信（装了的才有）；可增删 → 「下一步」/「先跳过」
③ 家人与联系人 填家人手机号（用于短信查位置）+ 可选加一两个联系人卡片 → 「下一步」/「先跳过」
④ 提醒与后台   推荐默认值：整点报时 开、天气播报 开、定时清理 开、通知白名单 默认那批
               → 「完成并进入主界面」/「用默认」
```

设计原则：

- **每一步都只是"预填"**，不是一次性决定，进主界面后都能在设置里改；
- **跳过不阻塞**：跳过就用默认值或空值，绝不弹"必须选择"；
- **不做联网限制这一步**（见上一节，多数机器不支持）；
- 向导结束前不给"进入主界面"以外的出口，避免家人迷路。

如果不想做向导，还有个更省事的替代：**首次直接进设置页**（把设置页顶部加一句"配置完成后点这里进主界面"），
配完再进主界面。这样只改一处代码，但体验比向导差——设置页信息量对家人来说偏大。

我倾向做向导，因为它的本质是"把必选项从 20 个减到 4 个问题"。

## 四、本轮已做 / 待做

已做（2026-10-25 第八轮）：

- 老人端顶部改成 **时间 / 星期 / 农历 / 节气**（离线算，不联网不引库）
- 老人端 App 名改「守护」
- 老人端**不再内置任何个人信息**（域名、Token 全空，需手填或扫码）
- 新增 `/status`（体检）与 `/track`（轨迹）接口
- 轨迹改为**老人端本地记录**：每 10 分钟看一次，动了（≥80 米）或超过 30 分钟才记一点
- 家人端改名「守护同步端」、换老年人图标、主界面标题「添加老人」、地址端口全部脱敏
- 家人端加「体检」「拉取轨迹」按钮

已做（2026-10-25 第九轮）：

- **4 步配置向导**：按上面定稿实现，每步可跳过；设置页也能重跑
- **移动数据限制开关**：Android 11+ 才真正生效，低版本明确说明不支持（本机 Android 10 实测显示"没有这个接口"）
- **老人端「轨迹」设置项**：开关 / 点数 / 一键清空

### 实现时发现的三个坑

1. `addSwitch()` 内部已经 `addView`，调用方不能再加一次，否则设置页直接崩（`IllegalStateException`）。
2. 向导第二步的应用列表有 30 多条，按钮放在列表下面要滚五屏——已移到列表上方。
3. 连点进设置时，第 9、10 下会漏到下层系统桌面（我们不是默认桌面），会误开别的应用；改为"凑够 8 下后等手指停 450ms 再跳"。

## 五、2026-10-26 重新评估：最低到底能到几

加了电量条、信号格、WiFi/数据开关之后重新核了一遍，**结论不变，但边界更清楚了**。

### 硬门槛（决定能不能装）

| 能力 | API | 最低版本 |
|---|---|---|
| `minSdkVersion` | — | **23（Android 6.0）** |
| DO 静默授予运行时权限 `setPermissionGrantState` | 23 | 6.0 ← **这是"装完就能用"的关键，5.x 没有** |
| 锁定任务 `setLockTaskPackages` / `startLockTask` | 21 | 5.0 |
| 禁止安装/卸载、防卸载自身 | 21 | 5.0 |
| 通知监听 `NotificationListenerService` | 18 | 4.3 |

### 新加功能的 API 要求（都不构成门槛）

| 功能 | API | 说明 |
|---|---|---|
| 电量竖条 / 信号格 | 无 | 纯自绘 View |
| `SignalStrength.getLevel()` | 23 | 正好等于 minSdk |
| `TelephonyManager.isDataEnabled()` | 26 | 低版本自动退回读 `Settings.Global.mobile_data` |
| `getDataNetworkType()`（判断 4G/5G） | 24 | 低版本返回空串，界面不显示制式 |
| 连接 WiFi：`WifiNetworkSpecifier` | 29 | 低版本走 `WifiConfiguration` 老路径 |
| 按应用禁用移动数据 | 30 | 只在 Android 11+ 出现，低版本明确显示"不支持" |

### 各版本的真实体验差异

| 系统 | 能用吗 | 要注意的 |
|---|---|---|
| **5.x** | ❌ 装不上 | 没有 DO 静默授权，权限要家人一个个点，体验直接崩。**不建议为了兼容 5.x 降 minSdk** |
| **6.0–7.1** | ✅ 能跑 | 没有通知渠道；部分国产 ROM 后台限制松但保活手段不同 |
| **8.0–9.0** | ✅ **推荐** | 通知渠道、前台服务都正常；**WiFi 还能由 App 直接开关**（`setWifiEnabled` 在 API≤28 有效） |
| **10（本机）** | ✅ 实测 | WiFi 开关被系统收回（只能引导去设置页）；移动数据任何时候都改不了 |
| **11–13** | ✅ 应该没问题 | 多一个「按应用禁用移动数据」；但 targetSdk 仍是 29，暂不受包可见性/前台服务新规约束 |
| **14+** | ⚠️ 待实测 | 若继续用 targetSdk 29，系统会提示"为旧版 Android 构建"，部分机型限制安装；升 targetSdk 需要补 `<queries>`、前台服务 type、精确闹钟等 |

### 一句话

**最低 Android 6.0（API 23），推荐 8.0 以上，本机 Android 10 实测全通。**
真要覆盖 5.x，代价是"权限得手动点"，把这套东西的核心优势（装完即用）丢了，不划算。
